# Deterministic cache policy

Repair `cache_api.simulate(config, operations)` in this synthetic stdlib mini-project. Three modules separate input schemas, cache policy and batch transactions. No real clocks, files, network or packages. Each simulation starts empty.

Config is exactly `{capacity: nonnegative_integer, default_ttl: null_or_nonnegative_integer}`. Bool is never an integer here. Operations must be a list. Each operation has a nonnegative integer now and op, and exact fields as below. Times must be nondecreasing across the batch (equal allowed). Keys are nonempty strings. Put has `{op:"put", now, key, value: any_JSON}` plus optional ttl (null or nonnegative integer); omitted ttl uses default_ttl; null means immortal. Get/peek/delete have exactly `{op, now, key}`. Resize has exactly `{op:"resize", now, capacity: nonnegative_integer}`.

Maintain entries in LRU-to-MRU order. Before EVERY operation, purge all entries whose expires_at <= now; record their keys in their current LRU order. An immortal entry has expires_at null. Put first removes the old key, then stores at MRU with expires_at now+ttl (or null). TTL zero and capacity zero do not store (and still remove an existing value); no eviction occurs for such a non-store. Otherwise evict oldest entries as necessary after insertion. Get hits move to MRU but do not extend TTL; peek hits do not move. Missing get/peek returns hit false and value null; stored null returns hit true. Delete removes a present key without affecting other recency. Resize replaces capacity and evicts LRU entries until it fits.

Return `{entries: [{key,value,expires_at}], capacity, results: [...], error: null}`. Entries are final LRU order. Each per-operation result includes op and expired (keys purged immediately before that operation). Put additionally has stored (bool), evicted (keys in eviction order). Get/peek additionally have hit and value (a snapshot at read time). Delete additionally has removed (bool). Resize additionally has evicted. No extra result fields. Values and read snapshots must be deeply detached from inputs and each other. Inputs must not be mutated.

Validate the ENTIRE batch before processing. Invalid config takes precedence and returns entries/results empty, capacity null, error `{code:"invalid_config",index:null}`. Invalid operations container returns entries/results empty, original config capacity, error `{code:"invalid_operation",index:null}`. First invalid operation (including backwards time) returns entries/results empty, original config capacity, error `{code:"invalid_operation",index:i}`. No partial state or earlier results on failure. Run `python -m unittest discover -v` in workspace.
