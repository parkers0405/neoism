`/connect` in the agent GUI (added 2026-07-08) opens a 3-stage picker mirroring opencode `auth login`, desktop-only for now:
1. **Connect a provider** — `NeoismAgentPickerKind::Connect`, Popular + Providers sections, ✓ on connected. Built from `GET /provider` (`{all, connected}`).
2. **Select auth method** — `ConnectAuth`, from `GET /provider/auth` (`{provider_id: [{type:api|oauth,label,prompts}]}`); the method **index** is the selector the server accepts.
3. **Secret entry** — `ConnectSecret`, the picker's own query row is the input field (reused via `search_placeholder`). API key → `PUT /auth/{id}` `{type:"api",key}`. OAuth → `POST /provider/{id}/oauth/authorize` (open URL in browser) then paste token → `POST /provider/{id}/oauth/callback` `{method,code}`.

Code: `neoism-frontend/desktop/src/neoism/agent/pane/connect.rs` (ConnectFlow + all methods); dispatch `SlashCommandAction::OpenConnectPicker` (shared `command_controller.rs`) → `commands.rs`; commit in desktop `pane/submit.rs` `commit_picker`; ESC steps back a stage in `pane/input.rs` `close_picker`. Shared `NeoismAgentPicker` gained `search_placeholder`; `InlinePickerView` too.

**Refinements (2026-07-08):** `/connect` now lists ONLY providers with a supported streaming adapter — server `provider_list` filters `all` by `provider_catalog::provider_connectable` (any model whose `api.npm` is in the allow-list, or openai). So the 7 unsupported (google/Gemini, amazon-bedrock, google-vertex-anthropic, aihubmix, gitlab, merge-gateway, sap-ai-core) are hidden from `/connect` entirely (no point connecting what can't run). `claude-code` is no longer force-shown in `/model` — `usable_provider_catalog` dropped its `=> true` branch so it must be connected like everyone else. Its `/connect` methods (`provider_auth_methods.rs`) are custom: **"Connect Meridian"** (one-click, GUI writes `PUT /auth/claude-code {type:api,key:"meridian"}` — a connected marker; streaming still uses the hardcoded `"dummy"` key via the Meridian proxy, `provider_anthropic.rs` `anthropic_key`) and **"Manually enter API Key"**. **Disconnect**: the auth-method stage prepends "Disconnect <name>" for connected providers → `DELETE /auth/{id}` (`connect.rs` `disconnect_connect_provider`, sentinel `DISCONNECT_VALUE`); env-var-only connections can't be removed from here. Meridian = the Claude Code proxy at `CLAUDE_CODE_PROXY_URL` (default `http://127.0.0.1:3456/v1`); requests carry `x-meridian-*` headers.

**xAI Grok OAuth + per-provider baseURL (2026-07-08):** Grok "SuperGrok" OAuth implemented server-side in `provider_auth_xai.rs` (mirrors `provider_auth_openai.rs`): loopback PKCE on `127.0.0.1:56121/callback` + headless device-code, reusing grok-cli's public client_id `b1a00492-073a-47ea-816f-4c329264a828`, `auth.x.ai/oauth2/{authorize,token,device/code}`, scope `openid profile email offline_access grok-cli:access api:access`, `plan=generic&referrer=opencode`. Loopback returns `method:"code"` (xAI redirects to `127.0.0.1:56121/callback?code=…` with no local listener → user copies the `code` and pastes it; `exchange_xai_loopback` has `extract_auth_code` that accepts a bare code / `code=…` / full URL). Device returns `method:"auto"` (background-poll `poll_xai_device`, user enters the user_code on xAI's page). So the loopback listener was dropped — the earlier auto-listener left the user with a code and nowhere to paste it. Stored as `AuthInfo::OAuth`; access token used as Bearer against `api.x.ai/v1`; refreshed by `provider_auth::refresh_oauth_if_needed` (called in the OpenAI-compatible chat runtime `provider_openai.rs` before key resolution — currently xai-only). Wired via `provider_auth.rs` authorize/callback xai branches + `provider_auth_methods.rs` (3 methods: SuperGrok loopback, Headless/Remote/VPS, Manually enter API Key). Generalized `provider_auth_browser.rs` listener with a `callback_path` param (openai `/auth/callback`, xai `/callback`). **Endpoint-URL model:** models.dev omits base URLs for native-SDK providers (xai/groq/mistral/anthropic/…); opencode lets the `@ai-sdk/*` package supply its baked-in default. neoism (no JS SDK) mirrors that with `default_base_url_for_npm` in `provider_catalog.rs` (unlocked 9 providers incl. anthropic + xai). Plus a per-provider override env `NEOISM_AGENT_BASE_URL_<ID>` (e.g. `_OPENROUTER`, `_CLAUDE_CODE`) via `provider_base_url_env_key` — wins over catalog+default; for gateways/self-hosted OpenAI-compatible servers. OpenAI/GitHub OAuth is `method:"auto"` (local callback auto-completes, no paste); generic providers are `method:"code"` (paste token). Provider layer is hand-built Rust (2 adapters: OpenAiCompatible bearer + Anthropic x-api-key), NOT the JS AI SDK. Headless server: `neoism_agent_server::listen(ServerOptions)`, OpenAPI at `GET /doc` (shallow — paths/operationIds only, no schemas).

**OAuth = no price + reasoning dedent (2026-07-08):** `provider_stream_message.rs::calculate_usage_cost` returns `Some(0.0)` when the provider's stored auth is `AuthInfo::OAuth` — subscription/OAuth accounts (ChatGPT, SuperGrok, Claude Code/Meridian) are flat-rate, so the sidebar shows tokens/context but no `$`. Token usage still tracked. Also: the "Thinking" panel showed random indentation because reasoning prose was rendered through the full markdown parser (leading whitespace → nested blocks); fixed in `view/assistant.rs::render_reasoning_message_with` via `dedent_reasoning_prose` (per-line `trim_start`, preserves fenced code) — render-only, can only shorten lines so no clip risk. xAI paste-field bug: `insert_paste` (desktop `pane/input.rs` + shared `state/input_edit.rs`) was routing long pastes to the composer as `[pasted …]` attachments; now any query-input picker (not Slash/FileMention/SkillMention) receives the paste into its query row.

**Why a provider is/ isn't in `/model`:** server `provider.rs::connected_ids` marks a provider connected iff it has an `auth.json` entry OR one of its models.dev `env` keys is set **in the agent-server process**. `usable_provider_catalog` then keeps only connected providers (plus opencode-free/claude-code). The embedded server runs *inside the GUI app process* (port 4096, PID = the `neoism` app), which under a desktop launcher does NOT inherit shell exports — so `OPENROUTER_API_KEY` in `~/.zshrc` was invisible. Fix: `neoism-frontend/desktop/src/agent_server.rs::hydrate_provider_env_from_login_shell()` runs `$SHELL -l -i -c env` once (bounded 3s) and imports `*_API_KEY`/`*_API_TOKEN`/`*_AUTH_TOKEN` before the server starts. Auth store = `~/.local/state/neoism/auth.json`; models catalog cache = `~/.cache/neoism/models.json`. See [[project_rust_owned_lsp]].
