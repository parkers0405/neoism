# Shared product docs in app builds

The source is the Git-pinned public submodule `vendor/neoism-docs`, not a user's Notes vault. After cloning (also before Docker builds), run `make docs-init` or `git submodule update --init --recursive vendor/neoism-docs`. Never use `--remote` in build/release automation: updating the submodule revision is an explicit source change.

`make docs` runs `npm ci` and `npm run build` in that pinned checkout, validates its self-contained `dist`, and stages only the site's contents into `neoism-frontend/gpuix/dist/resources/docs/`. The normal frontend release build calls the same helper automatically. The central docs revision must supply `package.json`, `package-lock.json`, and an npm `build` script; its artifact must include `api/docs/index.html`, `api/docs/reference/index.html`, and root `content.json` (valid JSON). Markdown, Notes, Git metadata, dependencies, symlinks and non-regular files are rejected in the artifact.

To build/stage without touching an installed frontend bundle: `node scripts/build-docs.mjs --out /tmp/neoism-docs-check/resources/docs`. To explicitly reuse a prebuilt shared-site artifact: `node scripts/build-docs.mjs --artifact /path/to/shared/dist --out /tmp/neoism-docs-check/resources/docs`. Normal builds and reuse require the complete central artifact contract (`manifest.json`, `artifact.json`, and `reference/openapi.json` as well as the entry routes and content); `content.json` must hash identically to the selected source's `bundle/content.json`. The selected source defaults to the pinned submodule, or can be set with `--source`. Reuse cannot silently ship another docs revision or bypass a missing checkout. Only explicit `--artifact ... --standalone` opts out of source matching for externally supplied artifacts/fixtures; it does not weaken any metadata validation where present.

To verify without building, installing dependencies, staging, or writing anything: `node scripts/build-docs.mjs --verify /path/to/resources/docs`. This checks all hashes and byte sizes in `artifact.json` when present, rejects missing/unlisted/unsafe inventory paths, and requires matching versions in content, manifest, and inventory. Add `--source vendor/neoism-docs` to also check the selected source's machine bundle. A standalone legacy/minimal artifact can omit metadata, but normal builds/reuse cannot. Inventory checks verify integrity and source matching verifies revision content; neither is a cryptographic signature authenticating an external publisher.

Linux tarballs/installers and Windows ZIP/MSI packages carry sibling `resources/docs`. macOS app bundles carry `Contents/Resources/resources/docs`, matching the local docs server's executable-relative lookup. Each contains the site directly, not another `dist` directory. Packagers fail if required docs are absent. No raw documentation content tree or user Notes vault is packaged.

Portable self-updaters include incoming `resources` in the hashed manifest and in the all-component staging/replacement/rollback transaction. Existing installations need not have that directory. Legacy payloads without `resources` remain recognizable; if a payload does include it, both HTML routes and nonempty valid JSON content are required. macOS bundle updates already copy/hash the entire app and now validate the docs subtree when present. Linux retains the old transaction tree (including docs) if a process is still mapped from its backup, rather than unlinking that process's executable-relative resources; such retained backups can be removed once their processes have exited. Windows retains its portable rollback directory as before.

`make docs-check` runs isolated Node fixtures (including a zero-dependency npm build). `python3 scripts/test-native-packaging.py` verifies Linux archive contents with fixture executables only. GitHub Actions check out submodules recursively; Nix's self source enables submodules and includes the shared source in its Rust fileset for the offline product-reference crate. Headless Docker services need the pinned reference content at build time but do not ship the browser site.
