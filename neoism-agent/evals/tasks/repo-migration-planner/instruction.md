# Migration planner

Repair `planner.plan(catalog, installed, targets)` in this synthetic stdlib repository. Source responsibilities: schema validation, graph ordering, and planning. No database or external dependencies.

Catalog is a list of exact records `{id, version, requires, transaction}`. IDs and dependency IDs are nonempty strings. IDs are unique; requires is a list of unique IDs (self-dependency is structurally valid but cyclic). Version is a positive integer excluding bool. Transaction is null or a nonempty string. Installed is a map of nonempty IDs to nonnegative integers excluding bool; unknown installed IDs are preserved. Targets is a list of nonempty IDs, with duplicates allowed. Inputs must not be mutated and returned containers must be detached.

Select the transitive dependency closure of targets, but skip a migration and its dependencies if installed[id] >= its catalog version. A target must exist in catalog even if installed. Every dependency of a selected migration must exist in catalog, even if present in installed. Check all catalog rows for structural validity, including unselected ones. Unselected graph defects do not matter. Installed dependencies at sufficient version are skipped. Never downgrade versions.

Return `{steps, versions, error}`. Each step is `{transaction: label_or_null, migrations: [ids]}`. Selected migrations sharing a non-null transaction label form one indivisible step. Null migrations each have their own step. Dependencies must precede dependents either within their step or between steps. Within a step use Kahn topological order, choosing the lexicographically smallest ready ID. Order steps with Kahn on the collapsed step graph, choosing the ready step with lexicographically smallest member ID. A transaction may pull together otherwise nonadjacent migrations. Versions is installed merged with selected catalog versions. Empty selection returns no steps.

On any error return empty steps, unchanged installed as versions, and `{code: CODE}`. Precedence: invalid_input (any schema defect); unknown_target; missing_dependency (reachable only); cycle (selected migration graph); transaction_cycle (acyclic migration graph becomes cyclic after grouping). Success error is null. Validation/selection/planning is atomic. All comparisons of IDs are Python string lexicographic comparisons. Run `python -m unittest discover -v` in workspace.
