Investigated upstream OpenCode V2 docs and dev commit df63a72da4b84c9983b6ddca46cd19f10caf4575. V2 core/cli/codemode package versions 2.0.27; npm @opencode/codemode latest verified 2.0.27. Legacy opencode-ai latest and GitHub latest still 1.19.0, so do not confuse channels. Code Mode is programmable tool composition, NOT an editor mode. Model submits {code}; Acorn parses JS and a custom confined AST interpreter executes it. No host eval, imports, process/filesystem or timers. Host tools/globals are explicit, JSON copied across boundaries; supports async calls, Promise composition, loops/branches/filtering, sync search({query,namespace,limit,offset}) returning exact callable paths/signatures. Pending work interrupted when program ends. Core adapter emits nested toolCalls progress, collects media and returns selected program output. Catalog budget ~2000 estimated tokens with namespace-aware selection/pinned tools and dynamic catalog instructions.

Important current V2 is HYBRID: native read/glob/grep/edit/write/patch/shell/webfetch/websearch/question/skill/subagent register codemode:false and are NOT accessible inside tools; MCP defaults true, alongside browser/session/worktree/MCP-resource namespaces. Opt-out remains possible. Runtime supports timeoutMs/maxToolCalls/maxOutputBytes but defaults unset and core adapter passes no limits. Core currently adds fetch as an explicit extension with 30s request timeout, despite docs claiming no fetch; do not blindly copy this policy.

Neoism current execute is MCP gateway search/call only, not JS. agent_tool_registry.rs:346 schema action enum search/call, :367 catalog summary (2000 CHARACTERS, shallow schema signatures), :678 one-tool dispatch. :476 MCP invocation already preserves raw response in metadata.mcp.result and attachments with permissions/cancellation. tool_runtime.rs:1164 execute_tool_call_in_generation is canonical hook/permission/approval/generation/session boundary; hooks run once before approval retry (:1203), output centrally bounded (:1286). Each script child must pass this boundary without replaying the script or duplicating prior side effects. provider_stream_processor.rs:987 existing semaphore/FuturesUnordered parallel native calls; avoid parent-held permit deadlocks when dispatching script children. plugin-api lib.rs:129 PluginToolDefinition has schemas but no composition eligibility; :170 PluginToolResult has string output/metadata, requiring explicit structured result contract for script data. shared agent_pane/api_mapping.rs:3133 labels execute search/call but lacks code card/child trace presentation. Existing bubblewrap plugin sandbox Auto may fall back native and isn't a cross-platform generated-code runtime.

Recommendation discussed only, no implementation: MCP-first hybrid composition, keep native coding tools direct; explicit eligibility enforced at dispatch; additive code execution action preserving existing gateway clients; isolated constrained runtime (evaluate Rust-embedded QuickJS worker vs packaged upstream TS interpreter sidecar; avoid building own JS language casually); no ambient fetch/env/filesystem/network; hard default CPU/wall/heap/tool/concurrency/output limits; stable scoped child broker, structured result/media handling, nested progress/audit stored separately from model context. Test approval pause, cancellation/partial effects, loops/heap, deny/hook enforcement, stale plugin generation, child concurrency and desktop/clipboard consent.
