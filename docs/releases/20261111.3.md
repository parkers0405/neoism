# Neoism v0.7.149-nightly.20261111.3

This Rune nightly follows `20261111.2`.

## Changes

- A window no longer sits connected to nothing after an update or a quick relaunch: an empty file tree and notes, a shell that runs nothing and prompts that are never sent, until the app was restarted. The app starts the workspace daemon when none answers. A daemon that finds another one holding the ownership lock exits at once, expecting that one to be used; when that other daemon was the previous version on its way out, nothing was listening a moment later, and the app waited out its whole start grace (two minutes, four on Windows) before trying again. The daemon the app started is now watched: one that exited is started again after three seconds, one still coming up is waited for as before.
- The status line says when no daemon is connected and why (`Starting the workspace daemon`, or the error), instead of leaving an empty window unexplained.
- A handshake the daemon refuses is no longer treated as a connection, and a daemon that accepted the socket has 30 seconds to acknowledge it and is not pinged before it does.

## Validation

The Rune app's 348 tests pass at this commit. The cause was found by reading the startup path of the app and the daemon; it was not reproduced on Windows or macOS, where it was reported, and the fix has unit coverage of the restart decision only. The status line notice was seen in a real window pointed at a daemon that does not exist. If the empty window still appears, the status line and `daemon.log` (in `~/.local/state/neoism`, or `XDG_STATE_HOME/neoism`) now say what the daemon did. The macOS and Windows builds are gated by CI only.
