Goal: completely remove embedded nvim; build a native, very-nvim-looking code editor pane that plugs into the existing neoism chrome. Zed is the architecture reference (`.reference/zed/` in-repo, current as of 2026-07-20 — NOT a sibling checkout; hidden dir). opencode vendored at `opencode/`.

**Survey findings (2026-07-20, 5 parallel explorers):**
- nvim is NOT a PTY TUI: msgpack-RPC `ui_attach` + ext_linegrid rendered into `Crosswords` grid. Two stacks behind `EditorBackend` enum (tab.rs:365): Local(`neoism-backend/src/performer/nvim*`, 7 files) + Daemon(`neoism-workspace-daemon/src/nvim/*`, 5 files) + 44 lua files. ~180 files reference nvim types; worst coupling = ~40 `editor_*` fields on `Context` (desktop tab.rs) + ~20 drain_* pollers. CRDT save seam: daemon `session.rs:1322` on_lines/BufWriteCmd → must be replaced by native buffer events into existing CRDT hub.
- LSP is ALREADY editor-grade + fully Rust-owned (post 4e5c08f9 overhaul): `neoism-agent-server/src/lsp*.rs`, live versioned didChange fed from buffer text, push+pull diagnostics broadcast bus, completion/hover/def/refs/rename/code-actions/formatting/symbols/call-hierarchy, position-encoding negotiation, per-workspace clients, ~20 servers in lsp_languages/registry.rs. Editor consumes via `EditorClientMessage::LspAction/LspComplete` ↔ `EditorServerMessage` over daemon ws; daemon bridge `language_server/{actions,queries,active_buffer,live_sync}.rs`. rio/lsp.lua is GONE. New editor = replace nvim as text source feeding `sync_document`/`flush_document_sync`. Gaps: full-doc didChange (not min-diff), no signatureHelp/inlayHint/semanticTokens/documentHighlight/foldingRange, blocking thread-per-client transport, possible 2-process engine split (desktop owns :4096 vs daemon), Drop-based child kill (no process group).
- Native substrate ~60-70% exists: sugarloaf `VirtualCodeAdapter` (virtual_surface/code.rs — CodeTile/CodeLine, built FOR this project, unused); MarkdownPane proves VirtualSurface end-to-end; sugarloaf SpanStyle has Curly underline + decoration_color (squiggles ready); Yrs CRDT plane text-generic (`editor/crdt/`, `MarkdownDocBinding` shadow-diff in doc_sync.rs works on Vec<String>); chrome all exists (status pill, breadcrumbs.rs path-strip, inline_diagnostics.rs, diagnostic_detail, completion_menu, hover_popup, minimap, buffer_tabs, cursorline_overlay) EXCEPT line-number gutter (net-new). Homegrown vim engine in shared editor/markdown/vim/ (resolver model.rs pane-agnostic; applier pane.rs coupled to MarkdownPane) — good operator/motion/text-object coverage; missing: visual-block, Ctrl-R redo, replace mode R, marks, macros, named registers. syntax.rs highlight_line = line-based tree-sitter for Rust/JS/TS/TSX only + keyword fallback; bundled .so parsers serve nvim only (die with nvim).
- File routing insertion point: `open_path_in_editor` (desktop screen/panes/open_create.rs:17) — final else → nvim is where CodePane slots in. New surface = `code: Option<CodePane>` field on Context + has_non_terminal_surface(); reuses SessionLeafKind::Editor.

**Architecture decision (recommended, awaiting user sign-off): adopt Zed's contracts, not Zed's code.** Keep Vec<String> lines + Yrs (porting Zed's SumTree/Rope/text-CRDT would conflict with the Yrs-everywhere sync model). Anchors via Yrs StickyIndex ≈ Zed Anchor. Adopt: background parse on snapshot + version recheck, chunks()-style styled-run feed (syntax+diagnostics merged), outline.scm ancestor-chain breadcrumbs, DisplayMap idea deferred (v1 = NoWrap, no folds ⇒ near-identity mapping). Zed build order (read display_map mod doc + lsp_command.rs): buffer/anchors → syntax → chunks → selections → LSP → diagnostics UI → outline → vim addon.

**Phases:** 0 CodePane core DONE 2026-07-20 (see below); 1 render (VirtualCodeAdapter, gutter, incremental whole-buffer tree-sitter + more grammar crates); 2 vim generalize + gaps (+ buffer trait extraction); 3 LSP wire (text source + squiggles + existing menus, + CodeDocBinding for Yrs); 4 breadcrumbs symbol trail; 5 nvim excision (~12 rs + 44 lua deleted, ~180 edits, protocol reshape not delete).
