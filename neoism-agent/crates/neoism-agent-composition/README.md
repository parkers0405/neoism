# neoism-agent-composition

A standalone, pure-Rust, bounded interpreter for composing a host's explicitly catalogued tools. Oxc 0.95.0 parses JavaScript modules with top-level await and top-level return enabled. The complete program is lowered into an owned, source-located AST before any tool call can happen. There is no JavaScript engine, eval, module loader, filesystem, network, process, timer, or ambient prototype API. Tools themselves are explicit host-provided capabilities, not ambient interpreter authority.

## Host contract

Implement `ToolHost::catalog` with unprefixed paths such as `neoism.read` or `github.list_issues`. Paths must consist of nonempty JavaScript identifier segments, be unique, and contain no forbidden prototype segments. `tools.neoism.read({ ... })` does an exact catalogue lookup. The interpreter never fabricates tool names. Catalogue generation should be fast and nonblocking; it is a synchronous host callback.

`execute(code, Arc<dyn ToolHost>, Limits, Arc<AtomicBool>)` runs inside a Tokio runtime. The external cancellation flag is read but never modified. Each run owns a separate local flag passed to every host call. The parent must bridge that flag to the canonical tool executor's cancellation mechanism. A host must honor cancellation for work it starts outside its returned future: Rust cannot undo a remote side effect or supervise tasks independently spawned by an arbitrary host.

Tool invocations immediately create supervised Tokio tasks, with total-call admission checked synchronously and concurrency admission enforced only around host calls. Async functions also create supervised tasks and return promises. Promises can be awaited repeatedly. `Promise.all` and `Promise.allSettled` poll their inputs concurrently, preserve input order, and share the run's fuel, data budget, cancellation and deadline. Promise.all rejects promptly on the first failure; sibling tasks remain owned by the execution. A caught rejection does not cancel siblings, while an uncaught rejection ends execution and triggers cleanup. No interpreter or host-call future is silently detached: normal completion signals local cancellation, joins within the cleanup deadline, then aborts and joins remaining tasks. Dropping the execute future also signals cancellation and aborts all registered tasks.

```javascript
const found = search({ query: "issue", namespace: "github", limit: 10, offset: 0 });
console.log(found);
const issues = await tools.github.list_issues({ state: "open" });
const selected = issues.filter(issue => issue.priority > 2);
return await Promise.all(selected.map(async issue => {
  const details = await tools.github.get_issue({ id: issue.id });
  return { id: issue.id, title: details.title };
}));
```

Discovery returns `{ tools: [{ path, description, signature }], total, offset, limit, nextOffset }`, where every path is an exact tool expression such as `tools.github.list_issues`. `nextOffset` is null at the end. Query matching is case-insensitive over the path and description; namespace matching is an exact dotted prefix. Defaults are limit 20 and offset 0; limit is capped at 100. Catalogue order is preserved.

## Supported subset

- JSON literals, dense arrays, plain objects (including shorthand keys), identifier bindings, dot/bracket reads, await, unary `!`, `+`, `-`, `typeof`, `void`, arithmetic, strict equality, ordered comparisons, short-circuit `&&`, `||`, `??`, and conditional expressions.
- Simple `const`/`let` declarations, lexical blocks, local assignment and arithmetic compound assignment, identifier increment/decrement, if/else, while, for, for-of over arrays, return, unlabelled break/continue, throw of primitives, and try/catch.
- Anonymous arrow/function expressions, sequential function declarations, lexical closures, async functions and async arrows. Parameters are simple identifiers. Catch binds a plain `{ message, kind, line, column }` error object (origin fields are null when unknown). Fatal resource/cancellation errors cannot be caught.
- Arrays: map, filter, flatMap, reduce, slice, find, findIndex, includes, indexOf, join, some, every, concat, push, and flat (depth 1 only). Push appends all arguments to the same array identity and returns its new length; const arrays, aliases and closures observe the change. Zero-argument push returns the current length. Admission reserves capacity/data and validates cycles and all retained parent depths under one state lock before any item is appended; a rejected multi-item push leaves the array unchanged.
- JSON.parse/stringify; Object.keys/values/entries/fromEntries; String and Number primitive conversions; Number.isFinite/isInteger; Math.abs/floor/ceil/round/trunc/sqrt/pow/min/max; bounded console.log/info/warn/error; Promise.all/allSettled.
- Strings: slice, indexOf, includes, startsWith, endsWith, split, trim, toLowerCase, toUpperCase, repeat, and literal first-match replace. IndexOf coerces the search string, truncates/clamps primitive fromIndex (negative/NaN to zero, positive infinity/beyond length to the end), handles empty needles, and returns Unicode-scalar indices or -1. A fuel-checked, cooperatively scheduled linear matcher allocates only admitted needle/prefix buffers, not a haystack character array or substring.

This is a bounded composition subset, not a claim of complete ECMAScript compatibility. Arrays and objects have shared mutable identity via execution-owned arena IDs; `const` protects a binding, not its contents. Aliases and closures observe property/index updates. Updates must use a local-rooted path with literal or identifier keys, and array assignment is limited to existing indices (use push to grow the same array, or concat to create a new one). Cyclic insertion is rejected before mutation, including cross-container cycles, so no Rust reference cycle can leak. Every ordinary `for-let` iteration receives a fresh environment, including the update transition. Computed effectful assignment targets are rejected during lowering. Async closures are concurrent Rust tasks; do not rely on ECMAScript's synchronous async-function prefix scheduling or deterministic ordering of captured mutable bindings. Use pure transformations or explicitly await dependent work. Function declarations are sequential, not hoisted. String indices/length use Unicode scalar values, not UTF-16 units. Primitive conversion and thrown-value handling are intentionally narrower than ECMAScript; the interpreter never invokes coercion hooks. String() produces an empty string; String(undefined/null/booleans/numbers) uses familiar primitive text. Caught diagnostic objects are tagged internally: String(error) and string concatenation produce `kind: message` without changing their original message/kind/line/column JSON fields. Plain data objects produce `[object Object]`, even if they contain a custom toString field; arbitrary hooks are never executed. Array/function/capability coercion remains unsupported (use join or JSON.stringify for data). Console logging a caught error retains readable bounded JSON diagnostic fields. Missing tool arguments default to an empty object, but explicitly undefined tool inputs (including nested fields/elements) are rejected. No-return/undefined top-level results become null; JSON.stringify omits undefined object properties and emits null for undefined array elements, and stringify(undefined) returns undefined.

JS Number values are f64. Finite integral values in the exact safe-integer range ±9,007,199,254,740,991 are emitted as JSON i64/u64 integers, so native serde integer fields and Value.as_u64 work for literals, lengths and arithmetic. Fractional values remain JSON floating-point numbers. Nonfinite and unsafe integral JSON values are rejected. Numeric literals, JSON.parse and incoming host JSON are checked before accepting values that could lose integer precision; use strings for larger IDs. Decimal fractions retain normal binary-floating-point rounding constraints.

Imports/exports, regex, template literals, optional chaining, destructuring, spread/rest, generators, new/constructors, classes, this/super, var, switch, do/while, labels, finally, delete, bitwise operators and coercive equality (`==`/`!=`) are rejected before effects. Unknown identifiers, unavailable tools, unsupported methods, non-data serialization, prototype access and invalid argument types produce explicit diagnostics. `__proto__`, `constructor` and `prototype` are blocked on reads, writes, object literals, parsed/host JSON, and Object.fromEntries. Builtins are explicit interpreter values, not arbitrary Rust closures; reserved global bindings cannot be rebound or shadowed.

## Static receiver preflight and effects

Runtime dispatch and static receiver preflight share a single supported-member table. Before executing any tools, preflight rejects unsupported members/calls on literal strings/arrays, explicit builtins (JSON/Math/Object/etc.), and simple known const/let receiver bindings, including immutable aliases and straightforward reassignments. It walks function bodies and branches too; it is not a reachability optimizer. The analysis is deliberately small and resource-bounded: object properties, function parameters/results and host data remain unknown, and mutable knowledge is discarded across branches, loops, callbacks and unknown function calls that could change captured state. It never globally bans member names on user objects/functions or tool namespaces; custom object functions and catalogued tools named push/indexOf remain allowed.

Composition is NOT transactional. Static syntax/receiver failures happen before effects, but dynamic receiver/argument failures, unavailable tools, host failures and limits may occur after earlier tools have run. Those effects cannot be universally preflighted or rolled back; tool-call traces preserve the earlier completed calls. Treat dependent actions accordingly and use explicit discovery/guards or host-side transactions when needed.

## Generic host result aliases

ToolHost has an optional `fn result_aliases(&self, tool: &str) -> &'static [ResultAlias]` with an allocation-free empty default. `ResultAlias { name: &'static str, path: &'static [&'static str] }` is an in-process host policy, not a JSON transport field. A host may return one canonical nested JSON result and supply static top-level alias names/path segments. The interpreter imports that result exactly once, then links aliases to existing owned arena handles/strings; it does not deep-import or JSON-clone the payload per alias. Aliases share array/object mutation identity with the canonical path. Replacing an alias or canonical field changes only that field; these are ordinary value references, not reactive path lenses. The imported data is execution-owned and cannot mutate the host's external serde_json values.

Aliases are limited to 32, paths are depth-bounded, and names/segments are limited to 1024 bytes and cannot contain prototype keys. Object-property and array-index path segments are supported; missing targets are skipped. Duplicate alias names or conflicts with existing root fields fail explicitly, so a host must remove redundant root fields before opting in. No existing fields are silently overwritten. Key/container admission and cycle/depth validation run before insertion; root/self aliases are rejected. An empty policy performs no extra alias allocation or fallback copy. JSON serialization of a returned whole result expands shared aliases normally and still obeys output/data/fuel caps; returning a selected view avoids duplicate serialized output. There is no lazy serialization layer or special knowledge of host transport schemas.

## Resource model

Defaults are 120 seconds, 100,000 steps, 64 host calls, concurrency 8, 64 KiB source, 64 KiB retained JSON/call-content output, 16 KiB logs, 16 MiB cumulative logical data allocation, and depth 64. Limits are public and can be reduced for tests or policy. Depth/source have hard ceilings of 64 / 64 KiB; promises have an additional hard ceiling of 4,096. Host concurrency is capped at 4,096. Cleanup defaults to 250 ms and has a 5-second ceiling.

The data budget is cumulative and conservative, not an exact process-RSS measurement. It accounts for source/AST capacity, static-preflight scope copies, environments, collections, strings, JSON conversion, task admission and retained call-input copies. Constructed data depth is checked before publication, and mutations validate all retained arena roots before changing shared nodes. JSON.parse performs an allocation-counting deserializer pass (nodes, decoded keys/strings, depth and numeric safety) before a DOM may be materialized. Every evaluated expression, statement, loop iteration, callback, JSON/data walk and discovery scan consumes fuel and checks deadline/cancellation. Cooperative scheduling checkpoints allow cancellation of synchronous spins on a single-thread Tokio runtime. JSON serializers use capped writers. Output-content retention is shared by the returned value and call input/error details; bounded call identity/status metadata and the result envelope are additional. Logs have a separate cap. Oversized output fails the execution; logs and call details are clipped/elided with `truncated` and a warning. Calls remain visible even when their input details are elided.

A conservative lexical complexity guard protects Oxc before recursive parsing: delimiter nesting, uninterrupted expression runs (512 non-whitespace bytes), and recursive operator/control-token count (256 per source) are bounded. This guard is not a JavaScript parser; Oxc remains the sole syntax parser. Quoted strings and comments are skipped; unsupported recursive introducers (including with/do/new), escaped identifiers, templates and regex literals are rejected before Oxc is entered. The guard tracks control parentheses to distinguish regex positions from ordinary division. It may reject otherwise valid unusually complex or ambiguous programs. Parsing/lowering are synchronous but bounded by source and complexity limits; host catalogue generation and arbitrary synchronous host code cannot be preempted by this interpreter.

Integration tests cover functional programs, dependent and reusable promises, real host parallelism with async map callbacks, discovery/pagination, branches/loops/closures, catchable host failures, pre-effect syntax rejection, cancellation, timeout, fuel/source/data/depth limits, noncooperative host cleanup, dropping execute, prototype/capability defenses, output/log bounds, source locations, and repeated-run isolation.
