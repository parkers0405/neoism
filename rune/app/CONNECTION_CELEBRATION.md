# Local connection celebration

User-initiated saved-server, server-form and saved SSH-system jobs converge in `servers/flow.rs`. Their `dial` completes a daemon Hello handshake (SSH first establishes its tunnel). Only consumption of that successful pending job starts Connected. Attempts, failed/cancelled jobs, local-tab selection, startup restoration and automatic tunnel redial do not. No protocol or backend change is needed. Disconnect dismisses the overlay.

Connected reuses goal celebration's actual lettering helper: bundled Press Start 2P, 28 logical points at baseline UI scale, shared activity glyph outlines and `PixelFire` textures, theme foreground and flame palette, borderless and inert. The transparent square animation sits below the text with one-em spacing. Small windows scale the entire composition to fit. Accessibility reduced motion, transparency or increased contrast uses static text without loading the artwork. Goal request UUID matching is unchanged.

## Local asset and provenance

The user supplied `~/Downloads/fist-bump-transparent.webp`, a processed transparent Finn/Jake fist-bump (400×400, 123 encoded frames, approximately 3.84 seconds), and authorized local implementation use. Original files remain untouched. Copyright ownership and redistribution permission are **unresolved**; no public permission is claimed. Do not commit, bundle, upload or publish this asset. This implementation contains no third-party artwork bytes.

The local copy is `~/.config/neoism/assets/fist-bump.webp`. The default follows Neoism's config directory, including `NEOISM_CONFIG_HOME`; an explicit process-local setting `NEOISM_CONNECTION_CELEBRATION_ASSET=/absolute/path/to/fist-bump.webp` overrides it. No hardcoded user home, Downloads fallback, network fetch or synced config is used. Missing/invalid files gracefully fall back to text and flames. Decoding happens only after confirmed success, on a worker, with 8 MiB encoded, 512×512 dimensions, 180 frames, 96 MiB decoded and eight-second duration caps. Composited WebP frames are decoded once; the UI uploads only on frame changes. Playback ignores the source loop count, holds the final frame for 600 ms (including a 450 ms fade), then drops textures and frames and stops waking. Loading has a two-second UI deadline.

### Source matte repair (highlight holes)

The later holes inside Finn's pale hand and Jake's yellow highlights were a separate asset-processing defect: `/tmp/fist_bump_key.py` used strict `red > green` as its opaque foreground test. The original GIF contains genuine highlights such as `[251,251,243]` and `[250,251,219]`, which that test discarded. Tiny screen-green GIF palette dithering also produced enclosed pinholes in hand shadows. `tools/rekey_fist_bump.py` now protects bright near-equal-channel foreground, fills only color-supported enclosed matte holes, and repairs tiny (at most 16-pixel) fully enclosed dither speckles separated from the exterior by foreground. Exterior-connected finger notches and larger green gaps remain transparent. Soft edge alpha and decontamination remain; there is no opaque bounding rectangle. The WebP disposal correction is retained unchanged.

The repair is local-only and accepts explicit original/output/review paths. Dependencies are Pillow, numpy and scipy (available locally in `/tmp/fist-bump-venv`). Example: `/tmp/fist-bump-venv/bin/python rune/app/tools/rekey_fist_bump.py "$HOME/Downloads/ceeb00c59b66af8ebd24c6fd2cdab0834f965403.gif" /tmp/fist-repaired /tmp/fist-repair-review`. It verifies all 128 source-frame masks, independently decodes WebP/GIF against the complete original timing, emits source-matte PNG references and all-frame checkerboard/contact sheets, and verifies that the original SHA-256 remains unchanged. The original SHA-256 is `aa13866826ff18951f72a167282acb2838bbce25837345516f53743869db63e0`. WebP remains 123 encoded frames (identical blank frames coalesced), 400×400 and 3840 ms.

### Decoder details

Live review found white/yellow slivers behind the hands. This was decoded-canvas residue, not surface damage: `image-webp 0.2.4` defaults its disposal background to `None`, leaving previous-frame pixels outside later frame rectangles. The decoder now explicitly sets RGBA `[0,0,0,0]` as its disposal background before iteration. Encoded blend/dispose semantics and fractional alpha remain intact; there is no opaque backing, thresholding or altered source file. Rune `Pixels::set` replaces the complete straight-alpha buffer and its atlas copies all rows, including transparent pixels, rather than blending updates together.

The first-party synthetic WebP regression verifies blank → opaque yellow → blank restores every vacated pixel to transparent. The optional local-asset test verifies both actual blank endpoint frames are fully transparent and soft edges survive. `NEOISM_CELEBRATION_CONTACT_SHEETS=1 ./rune/app/build.sh test celebration -- --nocapture` writes `/tmp/connected-decoder-before.png` and `/tmp/connected-decoder-after.png` directly from decoded CPU frames over black, isolating the cause from Rune. Corrected dark/light native captures are `/tmp/connected-live-{early,bump,finished}.png` and `/tmp/connected-light-live-{early,bump,finished}.png`. The opt-in `native_finished_captures_have_zero_residue` test checks every pixel in the finished central celebration area against the original background. Native captures are visual correctness checks, not presentation-timestamp benchmarks.

Build with `./rune/app/build.sh build`; run `./rune/app/build.sh test celebration -- --nocapture`. Offline scenes `connected` and `connected-light` avoid production connections. Example: `NEOISM_RUNE_OFFLINE=1 NEOISM_CONNECTION_CELEBRATION_ASSET="$HOME/.config/neoism/assets/fist-bump.webp" ~/.cache/neoism-rune-target/debug/neoism-rune --scene connected --snap /tmp/connected-dark.png --at 0.1`.
