# Clickable Fast Server invites

Fast Server clipboard links stay HTTPS, so Discord/email recognize them. Public Fast ingress GET / now serves a minimal responsive Neoism landing page using the SDK-owned canonical invite (never caller Host/forwarded headers). It attempts one `neoism://join?invite=<percent-encoded full HTTPS invite>` handoff and provides Open in Neoism, Copy invite, download, and manual Fast Join fallbacks. No browser IDE is exposed. HTML is escaped, CSP hashes restrict static script/style, responses are no-store/no-referrer/nosniff/frame-denied; passwords/master credentials are not placed in links. Fragment capabilities are not supported by the landing page, though the native legacy parser preserves valid capability fragments.

Native parser is `desktop/src/invite_links.rs`: strict neoism://join envelope, exact single invite query, 8KiB bounds, malformed escape/control rejection, and existing normalize_fast_join validation. Application invite queue is `app/invite_join.rs` (bounded, deduplicated FIFO). Cold-start CLI, Unix/Windows IPC, and macOS open_urls all route into it rather than creating file paths. Password-protected invitations prefill the existing Fast Join form and wait for explicit submit. Wrong passwords keep a correctable link/name, not a retained password; retries remove only failed unbound, non-hosted entries not used elsewhere. Permission/question/modals are not overwritten, and dirty server documents get a separate join window.

Linux packaged/bootstrap desktop entry uses %U and x-scheme-handler/neoism alongside file MIME types. Windows MSI and release/portable bootstrap register per-user neoism URL Protocol with quoted executable/argument; macOS already had Info.plist scheme registration. Bootstrap debug/Flatpak skips remain. A raw argv URI-only mode runs BEFORE Clap/internal services/update/auth/notes/terminal handlers: any case-insensitive neoism: operand (including malformed shapes and option assignments) ignores command/config-write/SSH/daemon/cwd/new-window/other operands. Normal CLI without a URI remains unchanged; mixed URI/file launches intentionally ignore files to prevent protocol argument injection. CLI helpers and IPC/RioEvent Debug redact URLs; activation tokens are bounded and redacted too.

Duplicate invites focus the actual adopted workspace, including mapping a hosted public origin back to its local endpoint. focus_fast_workspace invalidates competing endpoint/identity/credential generations and restores only a known active/parked transport. Temporary records may overlay a saved endpoint in memory: visible temporary row shadows the saved row, saved-ID lookups still work, and removing the temporary restores the saved row without changing persistent data or using saved credentials for a new external invite. Only accepted successful temporary non-host connections refresh their in-memory credential with connection.token(); failed authentication cannot overwrite a working password.

Server-switch request state now includes generation, endpoint, server ID, and credential. Different invite credentials/temporary IDs cannot coalesce with an older saved-server dial. Parked reuse honors an explicitly requested credential; a working parked connection is retained while authenticating a different credential. Current-generation failures and dirty-during-dial cancellation call invite_join_failed; completion clears invite attempt state before reset/parking and refreshes only temporary credentials.

Wayland foreground support forwards browser launcher authority: capture XDG_ACTIVATION_TOKEN / DESKTOP_STARTUP_ID before main clears environment, send an optional InviteActivationToken (1-4096 bytes, no control characters, serde validation, redacted Debug) over private IPC/Event. WindowExtStartupNotify::activate_with_token consumes supplied authority through existing xdg_activation on an existing surface without minting a background token or re-locking a state mutex; X11 uses startup notification plus best-effort focus. App retains authority for a valid invite until its actual target is ready: existing rendered/minimized windows activate immediately; cold windows wait until initial render. Native Window wrapper tracks has_rendered_frame. Browser token availability/compositor policy still control focus; never claim live activation was tested.

User's question about other server Edit options was READ-ONLY: no new server settings were exposed. Recommended future split: connection settings (name/address/client credential/status/test), owned-host settings (folder/port/auth plus explicit restart), Fast session settings (name/folder info/expiry/password rotation/guest controls). Current saved password edits the client's stored credential, NOT host-side password rotation. Access-role toggles need enforcement across files/Git/PTY/agents, not UI-only checkboxes.

Verification uses cargo check including test targets and wasm32 web compatibility; regression tests are compiled, not executed, no release build. Live browser handoff/OpenTunnel sharing and macOS/Windows activation remain unverified. Core paths: desktop app/invite_join.rs, app/invite_activation.rs, invite_links.rs, cli.rs, ipc.rs, bootstrap.rs, fast_servers/invite_page.rs; neoism-window startup_notify and Linux window implementations; backend event.rs; misc desktop/Windows/Mac packaging.
