# Neoism v0.7.153

Released 2026-11-14.

This stable release restores macOS workspace shortcuts, preserves the local glass cursor across remote connections, and includes all changes from the cancelled v0.7.152 batch. That release published no public desktop assets.

## Changes

- Restores Option+1..9 workspace switching on macOS by using physical number-row keys, because Option produces symbols instead of digit characters. Cmd+1..9 remains available as an alias.
- Fixes Agent Usage/Tasks/Goals cards swallowing Alt+Shift+Left/Right tab reordering and forwards application shortcuts from question-answer fields. Covers Home, regular Agent, question-answer, informational-card, and normal/insert-mode code input paths through the real keyboard dispatcher.
- Preserves the local glass cursor when joining a server or SSH system. Remote configuration cannot enable or disable the local material; Settings shows the effective choice, and unchanged remote polling does not request redraws. Local configuration and accessibility fallbacks remain in effect.
- Native touch panning and drag arbitration, scrolling and selection refinements, configurable fonts and keybindings, and macOS glass cursor rendering with ordinary fallback behavior elsewhere.
- Agent goal lifecycle and completion feedback, activity presentation, slash commands, tool cards, and conversation controls.
- Workspace file handling, connection and server-availability feedback, compact finder/palette layouts, and Linux updater restart improvements.
- Pinned vendored Rune input/rendering changes, including upstream GPU libraries and binary fixtures required for fresh checkouts.

## Verification

Focused checks passed on macOS in `rune/app`: `./build.sh test --locked keys::tests` (8 passed, including eight real-input tab-reordering states) and `./build.sh test --locked liquid_glass -- --nocapture` (5 passed). The final remote cursor regression was rerun through inbound config dispatch (1 passed), covering direct servers and SSH systems, absent and explicit remote overrides, local reloads, Settings consistency, and unchanged polling. The locked root manifest also passed offline Cargo metadata validation. These checks cover keyboard and configuration behavior; the full test suite was not run. This is not a claim of exhaustive GUI, provider, touch-device, or cross-platform validation.

## Release packages

The existing incremental platform release workflow is unchanged. Linux x86-64, macOS ARM64, and Windows x86-64 build from the same stable tag. Each platform uploads its downloads and publishes the shared release as soon as its own job succeeds; another platform's failure does not block it. The daemon container image uses its separate workflow.

Existing GitHub platform build, test, and packaging steps remain enabled. Existing database backup and downgrade cautions remain applicable. Ignored local build outputs and private workspace state are excluded.
