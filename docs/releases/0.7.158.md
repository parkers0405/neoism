# Neoism v0.7.158

Release preparation date: 2026-11-17 (host local date).

## A steady 120 frames a second in Agent conversations

Agent conversations on a 120 Hz Mac read 100 to 120 on the FPS badge while scrolling, streaming and running tools. Two causes, both fixed.

- **Frame pacing.** Rune's macOS display-link rule skipped a tick that came less than half a refresh period after the last submission. A frame started on a tick that took more than about 3.7 ms therefore always cost the next refresh: 4 ms of work a frame drew at 64 frames a second, with more than half the period unused. A tick is now skipped only when the previous frame was submitted after that tick ran (it overran its own slot). Frames hold 120 up to about 6 ms of UI-thread work.
- **Streaming cost that grew with the reply.** A text element is shaped whole whenever it changes, and a reply was only cut into cached pieces at headings. A long code block or a long section without headings was rebuilt whole thirty times a second: a 900-line file cost 20 ms of every update by its end (about 37 frames a second), and 40 KB of prose 7 ms. Replies are now also cut at paragraphs, with the same spacing as before, and code blocks of 48 lines or more are drawn in 32-line slabs with highlighting computed across the whole block. Each update costs what its last piece costs (about 3 ms in both cases).

Rendering is unchanged: screenshots of long code blocks, comments spanning slabs, and prose cut at paragraphs, lists, quotes, rules and headings match the previous release to within one pixel of glyph rounding.

## Measuring it

`rune/scripts/check-live-pacing-macos.py` runs a scripted workload in a real window against the real daemon and reports missed refreshes from Metal presentation times. Its `hand` step scrolls as a hand on a trackpad does: precise scroll events with finger and momentum phases, flicks, reading drags, reversals and pauses on their own jittered clock, delivered through the real input path. `RUNE_TRACE_TICKS`, `RUNE_TRACE_GPU` and `NEOISM_RUNE_BURN_US` expose display-link decisions, GPU timing and the per-frame budget.

## Verification status

On an M5 Pro at 1728x1050, against real conversations: idle, hand scrolling through paged history (310 to 1,242 messages), live tool rows, streaming (mixed reply, a 900-line code block, 40 KB of prose), streaming while scrolling, and mouse wheel all presented at 120.0 with zero missed refreshes in the final capture. A 150-second real model turn that read and patched files and wrote a long summary, scrolled by hand throughout, presented 17,988 frames with one missed refresh.

All 592 macOS unit tests and the GPU scroll-image test pass when run serially (eight registry tests interfere with each other when run in parallel, as before this change). Linux and Windows were not run locally; the release build validates them.

## Release packages

Linux x86-64, macOS ARM64, and Windows x86-64 build from the stable tag. All three platforms publish independently: each successful platform publishes without waiting for the others. The daemon container image retains its separate workflow.

Existing database backup and downgrade cautions remain applicable.
