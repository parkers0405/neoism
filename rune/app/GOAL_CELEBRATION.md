# Goal-start celebration

`src/goal_celebration.rs` owns a finite, inert Rune overlay. A locally submitted new goal arms intent (including the new-conversation path). Only the daemon's live `MessageUpdated` projection of the server's persisted `goal_started` completed tool notice can consume it. The session, goal text, exact request-derived notice ID, system kind, title, tool and status must match. Snapshots/history do not start it. Errors clear pending intent; disconnect clears both intent and the animation. Resume is deliberately not a new-goal celebration. A queued start retains intent rather than timing out before its turn begins.

Confirmation is independent of wall clocks and receipt-time heuristics. New goals use the existing goal-aware `SubmitPrompt` path with a fresh UUID `message_id`, no optimistic ordinary-prompt echo, and no model/agent overrides (the selected session defaults are preserved). The daemon's `goals::execute_with_prompt` preserves this ID, and the agent server derives the completed marker ID as `prt_goal_started_<message_id>`. The UI accepts exactly that marker then consumes the pending intent. Old markers cannot match a fresh UUID, even after rearming with identical goal text; there is no finite replay-cache eviction window. Non-start slash commands retain their original path. Production daemon/backend and protocol code are unchanged.

The indicator is centered horizontally and vertically in the full app window, independent of panes, rails and composer placement. It reads **Goal started** in the exact bundled Press Start 2P family, regular weight and one-em line height used by Crafting, via the shared `agent::activity::flames::font` helper (scaled to 18 logical points). There are no custom specular bands, rainbow highlights, underline or particles. It expires after 1.8 seconds, fading only during the final 450 ms when motion is allowed.

Fire is the existing renderer, not an approximation or a new shader: `wordmark/fire.rs` and `agent/activity/flames.rs` both use `ui::fire::PixelFire`. Goal lettering reuses the activity glyph cache, seeds, 16 Hz animation and exact supersampled RGBA conversion through the minimally factored `flames::rgba` helper. Texture placement uses Crafting's half-cell overlap with the actual glyph edge. The two extra outlines (`G`, `l`) were checked against the bundled TTF using CoreText path sampling at each 125-unit pixel cell. Shared `ui::fire::colors` supplies classic flames for Neoism themes and theme-derived flames elsewhere; the existing wordmark-fire toggle is respected. No changes were made to the splash renderer or native cursor/rail materials.

The subtree is `inert`, positioned independently of layout, and below interactive popups. It never changes composer text, selection, focus or cursor state. Live bindings animate without per-frame view commits; one final commit removes the subtree and stops its wakeups. Leaving the session also dismisses it. Normally the lettering and flames float without a card, fill, or border. macOS accessibility reduce-motion/reduce-transparency/increase-contrast settings select plain static text with an opaque theme-background backing for legibility; other platforms can use `NEOISM_REDUCED_MOTION=1`, `NEOISM_REDUCED_TRANSPARENCY=1` or `NEOISM_HIGH_CONTRAST=1`. There is no persisted setting or Settings toggle for this feature.

## Verification

Run `./rune/app/build.sh test goal -- --nocapture`, `./rune/app/build.sh test flames -- --nocapture` and `./rune/app/build.sh build`. Tests cover centered geometry at multiple window/font sizes, shared fire pixel output and animation in four themes, exact request confirmation, replay/dedup/errors, input preservation and finite lifetime. Capture offline so daemon workspace restoration cannot replace the fixture: `NEOISM_RUNE_OFFLINE=1 NEOISM_CONFIG_HOME=/tmp/neoism-goal-review-config ~/.cache/neoism-rune-target/debug/neoism-rune --scene goal-celebration --snap /tmp/goal-fire-dark.png --at 0.1`. Use scene `goal-celebration-light` for light mode, or add `NEOISM_REDUCED_MOTION=1` for the static version. The fixture starts 550 ms into the shared fire animation. The screenshot runner's synthetic `--at` time does not advance this feature's wall clock; finite finish is tested by advancing its stored start Instant. Headless captures are not presentation-timestamp performance measurements.

Live verification uses an isolated offline process and captures only its own window ID, not the desktop. The temporary helper `/tmp/goal-live-capture.swift` launches the debug binary with `NEOISM_RUNE_DRIVE=wait:5;quit`; driven fixtures start at zero rather than the headless sample offset. Captures are `/tmp/goal-celebration-live-active.png`, `/tmp/goal-celebration-live-finished.png`, and the corresponding `goal-celebration-light-live-*` files. The finished captures verify the overlay is gone. These are rendering/lifetime checks, not frame-pacing benchmarks.
