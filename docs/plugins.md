# Neoism plugin authoring

This is the canonical authoring guide for Neoism packages that extend the editor and, optionally, the Agent. It documents the checked-in API version `1` contracts; when prose and code disagree, the linked Rust DTO and registry are authoritative.

For callable editor signatures, install or open [`docs/lua-api.lua`](lua-api.lua), which is generated by `neoism_lua::generate_lua_api_annotations` and checked for drift. For the complete editor surface and DTO tables, continue with [Editor plugin API](editor-plugin-api.md).

## Architecture and invariants

Neoism's plugin boundary is data-oriented: Lua callbacks publish immutable contributions or enqueue typed host actions, while Rust owns editor state, layout, rendering, input routing, parsing, transport, process supervision and mutation validation.

Rendering and shared text state remain Rust/CRDT-owned. No plugin runs on render, layout, animation, scrolling, pointer hit-test, input, timer, process-reader, watcher, network, language-server, daemon or GPU threads; callbacks run on the application Lua executor, and renderer-facing state contains no Lua callback or VM references.

Each package runs in an isolated Lua 5.4 VM and is identified by the exact pair `{ pluginId, revision }`. The revision is content-derived from the entrypoint and contained `lua/**/*.lua` files; callbacks, asynchronous requests, opaque resources, approvals and cleanup are bound to that exact owner.

The host never retargets a stale document, pane, tab, workspace, request or resource to whatever is currently focused. Opaque handles must be retained and returned unchanged, never parsed or constructed.

Editor coordinates are zero-based lines and zero-based UTF-8 byte columns. This is not UTF-16 and not Unicode-scalar indexing; validate byte boundaries before constructing edits.

Local view state includes cursor, selections, focus, geometry, visible ranges, scroll and overlays. Shared document edits pass through Rust's normal buffer and CRDT transaction path; plugins do not own an editor state machine or a CRDT document.

## Package layout

A local development package is a directory below `~/.config/neoism/plugins/<package-id>/`. A minimal editor package is:

```text
~/.config/neoism/plugins/dev.example.word-tools/
├── neoism-plugin.json
├── init.lua
└── lua/
    └── word_tools/
        └── transform.lua
```

`require("word_tools.transform")` may resolve only `<package>/lua/word_tools/transform.lua` or `<package>/lua/word_tools/transform/init.lua`. Module names may contain ASCII letters, digits, `_` and `-` in non-empty dot-separated components; traversal, absolute paths, native modules and external Lua search paths are rejected.

The sandbox removes `io`, `os`, `debug`, `dofile`, `loadfile` and `package.loadlib`, sets `package.cpath` to the empty string and replaces `package.path` with the package-contained paths. Filesystem, network, process and credential work must use brokered host operations.

## `neoism-plugin.json`: canonical shared schema

The editor's exact discovery DTO is `PluginManifest` in [`types.rs`](../neoism-lua/src/types.rs), with `camelCase` fields, accepted `api_version` alias, defaults, and no `deny_unknown_fields`. The Agent's shared package DTO is `NeoismPackageManifest` in [`package.rs`](../neoism-agent/crates/neoism-agent-plugin-api/src/package.rs), also `camelCase`, with `api_version` accepted as an alias. Both readers accept the canonical nested `editor` and `agent` targets.

Use `editor.entrypoint` for new packages. The legacy top-level `entrypoint` remains accepted for existing editor-only packages; when both are present, `editor.entrypoint` takes precedence. The separate top-level `entrypoints` object declares optional trusted editor extension tiers and is not the Agent target.

```json
{
  "id": "dev.example.word-tools",
  "name": "Word Tools",
  "version": "1.2.0",
  "apiVersion": 1,
  "editor": {
    "entrypoint": "init.lua"
  },
  "agent": null,
  "platforms": ["linux", "macos", "windows"],
  "dependencies": [],
  "triggers": [
    { "kind": "command", "value": "word-tools.sort-lines" },
    { "kind": "filetype", "value": "markdown" }
  ],
  "capabilities": [
    "document.read",
    "document.write"
  ],
  "metadata": {
    "license": "MIT"
  }
}
```

### Editor manifest fields

| JSON field | Type | Default | Rules |
|---|---:|---:|---|
| `id` | string | `""` | Required in practice; lowercase reverse-DNS, at least two dot parts; each part starts lowercase and then contains lowercase ASCII, digits or `-`, and does not end in `-` |
| `name` | string | `""` | Human-facing name |
| `version` | string | `""` | Package version; managed acquisition records it but does not impose SemVer parsing here |
| `apiVersion` | integer | `1` | Must equal host `neoism_lua::API_VERSION`; `api_version` is an accepted alias |
| `editor` | object or null | `null` | Canonical editor target `{ "entrypoint": string }`; its contained relative entrypoint takes precedence over the legacy field |
| `entrypoint` | string | `"init.lua"` | Legacy editor-only entrypoint retained for compatibility; contained relative path naming a file with no absolute path, `.` or `..` component, or canonical escape |
| `platforms` | string[] | `[]` | Empty means all; otherwise unique members of `linux`, `macos`, `windows`, including the current host |
| `dependencies` | string[] | `[]` | Unique package IDs; every dependency must exist and the graph must be acyclic |
| `triggers` | trigger[] | `[]` | Unique by computed key; empty or `Startup` means eager activation |
| `capabilities` | capability[] | `[]` | Unique by computed key; declaration alone does not grant authority |
| `entrypoints` | object | `{}` | Optional `uiLua`, `editorLua`, `agent`, `subprocess`, `native`; see extension tiers below |

The shared package DTO additionally accepts `agent` and `metadata`; its defaults are `apiVersion: 1`, empty arrays/maps, and null targets. `agent` is described below.

### Triggers

A trigger is either a string or an object `{ "kind": string, "value"?: string, "mode"?: string, "when"?: string }`. Its uniqueness/index key is `kind` when `value` is absent and `kind:value` when present.

| Trigger | Example | Behavior |
|---|---|---|
| startup | `"Startup"` or `"startup"` | Eager load |
| command | `{ "kind": "command", "value": "word-tools.sort-lines" }` | Publish a lazy command placeholder and activate before invocation |
| event | `{ "kind": "event", "value": "DocumentOpened" }` | Activate on the indexed event trigger |
| key | `{ "kind": "key", "value": "g s", "mode": "normal", "when": "editorFocus" }` | Intercept, activate off the input path, republish, then replay exactly once |
| filetype | `{ "kind": "filetype", "value": "rust" }` | Activate for the authoritative editor filetype |
| surface | `{ "kind": "surface", "value": "notes" }` | Activate when the named surface becomes active |

Trigger kinds and values other than those consumed by the current manager are syntactically accepted but have implementation-defined activation behavior. Do not assume an unlisted trigger fires merely because it validates.

### Capabilities and grants

A capability is either a string or `{ "name": string, "scope"?: string }`; the detailed key is `name` or `name:scope`. At runtime, effective editor grants are the intersection of manifest declarations and the user's `plugins.grants` entry.

The host action registry derives capability names as `<namespace>.<access>`, such as `document.read`, `document.write`, `job.execute`, `network.execute`, `lsp.read`, `lsp.edit`, `lsp.cancel`, `git.read`, `git.write`, `agent.read`, `agent.write`, `debug.execute`, `debug.write`, `pty.execute` and `pty.write`. Exact mappings are returned in `neoism.contract` and defined by [`action_contract`](../neoism-lua/src/contract.rs) and [`query_contract`](../neoism-lua/src/contract.rs).

Platform declarations report these intended registration capabilities: `ui.write`, `completion.register`, `lsp.register`, `syntax.register`, `task.register`, `debug.register`, `terminal.register`, `git.register` and `agent.register`. Invocation still passes through the operation-specific broker; current declaration-time enforcement is host-defined, so declare and request both registration and use capabilities.

The user's grouped `config.json` policy uses kebab-case keys:

```json
{
  "plugins": {
    "disabled": [],
    "grants": {
      "dev.example.word-tools": [
        "document.read",
        "document.write"
      ]
    },
    "update-policy": "notify",
    "trusted-sources": [
      "https://github.com/example/"
    ]
  }
}
```

`update-policy` is `manual`, `notify` or `automatic`. `trusted-sources` is an optional prefix allow-list for managed Git URLs; an empty list accepts any otherwise-valid credential-free HTTPS source.

## Optional Agent entrypoint

The shared package `agent` object uses `camelCase` fields:

```json
{
  "runtime": "lua",
  "entrypoint": "agent.lua",
  "command": [],
  "capabilities": ["workspace-read"],
  "scope": "workspace",
  "eventNamespaces": ["dev.example.word-tools"]
}
```

`runtime` is `lua` or `process`; `scope` is serialized with the `PluginScope` contract from the Agent API; `command` is for process entrypoints. Agent capabilities are the `HostCapability` kebab-case enum, not editor capability strings; consult [`neoism-agent-plugin-api/src/context.rs`](../neoism-agent/crates/neoism-agent-plugin-api/src/context.rs) and [`package.rs`](../neoism-agent/crates/neoism-agent-plugin-api/src/package.rs) rather than guessing names.

Agent Lua runs in the separately packaged supervised `neoism-agent-lua-runner`, not the embedded editor VM. The two runtimes share package identity and revision intent but not globals, callbacks, state or authority.

## Declarative installation specs

Declarative specs live in `~/.config/neoism/lua/plugins/*.lua`. Each file must return one spec or an array of specs; evaluation has an 8 MiB memory limit, a 50 ms budget, no `io`, `os`, `debug`, `require`, `dofile`, `loadfile`, `load` or `package`.

```lua
return {
  id = "dev.example.word-tools",
  source = {
    type = "git",
    url = "https://github.com/example/neoism-word-tools.git",
    rev = "v1.2.0",
  },
  enabled = true,
  revision = "",
  config = {
    sort_case_sensitive = false,
  },
}
```

`PluginSpec` fields use `camelCase`: `id`, `source`, `enabled` (default `true`), `revision` (opaque string) and `config` (default object). Source is a `type`-tagged kebab-case enum: `{type="local", path}`, `{type="git", url, rev?}`, or `{type="registry", id, version?}`; registry acquisition is currently not implemented.

Managed Git requires a credential-free HTTPS URL with a host and without traversal, query, fragment, username or password. Plugin IDs are at most 128 bytes of ASCII alphanumeric, `-`, `_` or `.`, and refs are bounded and reject control characters and dangerous Git ref syntax.

The application clones to staging, resolves an exact commit, checksums the tree, validates the manifest without allowing the validator to modify it, publishes an immutable commit-addressed revision and atomically replaces `plugins.lock.json`. Failed acquisition, checksum, validation, candidate composition or publication leaves the last-known-good revision active and restores the prior lock entry.

The lockfile is host-owned JSON with version `1`; its Rust field names currently serialize as snake_case: `plugin_id`, `repository_url`, `requested_ref`, `resolved_commit`, `plugin_version`, `manifest_checksum`, `tree_checksum`, `dependencies`, and `installed_revision_path`. Authors must not edit it.

## Lifecycle

1. Discovery reads local manifests and enabled specs in deterministic order without executing package code.
2. Validation checks identity, API version, entrypoint containment, platform compatibility, duplicate declarations, dependency existence/cycles and tiered entrypoints.
3. Triggerless and startup packages are candidates immediately; lazy packages publish only placeholders.
4. Dependencies are activated first in stable topological order.
5. Each package builds in a fresh isolated VM with its content revision, budgets and attenuated host grants.
6. The manager validates the complete combined snapshot for conflicts, surface geometry and retained contribution limits.
7. Only a valid whole candidate is activated and published; rejected candidates cannot commit persistent state or host mutations.
8. On reload, disable, update, removal or failure, the old exact owner is retired; its timers, jobs, watchers, prompts, pending results, PTYs, DAP sessions, resources and ephemeral state are cancelled or removed.

Inventory lifecycle names in the editor manager are `discovered`, `lazy`, `loaded`, `disabled`, `update-available`, `permission-required`, `approved`, `revoked`, `incompatible`, `blocked`, `failed`, and `restore-required`. The broader shared package DTO uses kebab-case `discovered`, `incompatible`, `permission-required`, `trusted`, `enabled`, `loading`, `active`, `degraded`, `failed`, `disabled`, `update-available`, and `restoring`; consumers must not assume the two UI projections are identical.

Reload is transactional. Invalid Lua, an unknown autocmd event, a dependency cycle, a duplicate command or panel, an invalid retained view, a style/DTO serde error, an unknown surface, a bad artifact, or a capability/trust failure leaves the previous generation live whenever a previous generation exists.

## Trust, scopes and security boundaries

Sandboxed Lua is the default tier, but sandboxing is not capability: every host query or action is resolved through the typed registry and checked against the effective grant set before application dispatch. A manifest can request authority but cannot grant it.

Execution scopes are serialized as kebab-case: `local`, `workspace`, `shared-buffer`, and `presence`. An operation has one registry-defined scope; passing a different scope through `.call` is rejected before privileged dispatch.

`local` affects the requesting application/window, `workspace` is a daemon-authoritative workspace/layout or resource operation, `shared-buffer` is a Rust/CRDT-owned document transaction, and `presence` is ephemeral collaboration metadata. A scope is an execution-routing invariant, not a substitute for a capability grant.

### Extension tiers

| Serde value | Meaning | Approval |
|---|---|---|
| `sandboxed_lua` | Isolated embedded editor Lua | Default tier; host capabilities still require grants |
| `trusted_subprocess` | Supervised executable extension | Exact external approval required |
| `trusted_native` | Supervised native ABI artifact | Exact external approval required; native ABI is currently `1` |

`entrypoints` has the exact `camelCase` schema `{ uiLua?: string, editorLua?: string, agent?: string, subprocess?: string[], native?: OpaqueArtifact }`. `OpaqueArtifact` is `{ resource: string, sha256: string, abi?: integer, platforms?: string[] }`; `sha256` is exactly 64 hexadecimal characters, and `resource` is opaque.

Executable/native approval records live outside repositories and are exact over plugin ID, content revision, package SHA-256, artifact SHA-256, ABI version, the full capability set and user/workspace scope. Changing any bound value requires a new approval; workspace code cannot approve itself.

The trust store's private JSON DTO uses `camelCase` fields and `deny_unknown_fields`; scope is internally tagged as `{ "kind": "user" }` or `{ "kind": "workspace", "workspace": "..." }`, and state is `permission_required`, `approved`, `revoked` or `failed`. The store is host-owned, atomically written and mode `0600` on Unix; authors must use the Extensions UI, not edit it.

Tree-sitter native parser artifacts require immutable checksum validation and ABI `13`, `14` or `15`. Native/parser code is loaded only in supervised child Neoism processes after platform, symbol, digest, ABI and exact-approval checks.

Credentials are opaque aliases backed by the OS credential vault. Lua can request alias availability and attach an alias to an HTTPS request, but it never receives the secret; the broker injects a Bearer header only for an exact owner, scope, `network.authorize` grant and allowed host.

## Compatibility rules

Check `neoism.api_version == 1` before depending on version-specific behavior, inspect `neoism.contract` for coordinate encoding, events and typed host metadata, and inspect `neoism.extension.capabilities` for platform, scopes, contribution kinds, registered host-operation names and extension tiers.

Treat unknown fields in output as forward-compatible and do not depend on map ordering. For input DTOs marked `deny_unknown_fields`, misspellings fail the candidate or request instead of being ignored.

Do not construct host handles, infer filesystem paths from `hostPath`, retain handles past closure, reuse asynchronous IDs across owners, or persist revision-scoped opaque resources. Persist only your own logical data under permitted plugin/workspace state.

Platform declarations and broad host-operation families are portable contracts, but a particular frontend can return an explicit unsupported/failure result or have no adapter for a declared operation. Such adapter details are implementation-defined; probe capabilities, handle failures, and never infer support from a DTO alone.

## Minimal copy-ready editor plugin

```lua
local neoism = require("neoism")
local transform = require("word_tools.transform")

neoism.setup({
  word_tools = {
    sort_case_sensitive = false,
  },
})

neoism.ui.style("editor", {
  accent = "#7aa2f7",
})

neoism.command.register("word-tools.sort-lines", function(event)
  local document = neoism.document.current()
  local lines = neoism.document.lines({ document = document.handle })
  local last_line = math.max(#lines - 1, 0)
  local last_character = #(lines[#lines] or "") -- Lua string length is bytes.
  local replacement = transform.sort(document.text, event.payload.arguments or {})
  return neoism.document.edit({
    document = document.handle,
    expectedRevision = document.revision,
    edits = {
      {
        range = {
          handle = "",
          start = { line = 0, character = 0 },
          ["end"] = { line = last_line, character = last_character },
        },
        text = replacement,
      },
    },
  })
end, {
  title = "Sort lines",
  description = "Replace the current document with sorted lines",
  arguments_schema = { type = "object" },
  result_schema = { type = "object" },
})

neoism.keymap.set("normal", "g s", "word-tools.sort-lines", {
  when = "editorFocus && normalMode",
  priority = 10,
  fallback = true,
})
```

## Error model and debugging checklist

Load-time failures include malformed JSON/Lua, invalid manifest identity or containment, incompatible API/platform/ABI, missing or cyclic dependencies, duplicate graph keys, memory/time budget exhaustion, invalid serde casing, unknown autocmd events, unknown augroups, contribution conflicts and invalid retained snapshots.

Dispatch-time failures include an unregistered namespace/action pair, wrong execution scope, undeclared or ungranted capability, missing exact owner, retired generation, stale handle/revision, wrong target kind, cross-owner resource, malformed request, budget/queue limit, workspace escape, unsupported adapter and cancellation.

Asynchronous failure is delivered through `LspResult`, `CommandResult` or `AsyncResult`; do not wait synchronously. Cancellation is logical: the host emits one terminal cancellation, suppresses late results and attempts resource/process teardown, but it does not promise that an external server received a protocol-level cancellation.

When a package remains lazy, verify the trigger's computed key exactly matches `command:<id>`, `key:<key>`, `filetype:<language>` or `surface:<name>`. When an operation is denied, compare the exact capability in `neoism.contract` with both the manifest and `plugins.grants`.

When serde rejects a table, compare casing against this guide and [`docs/lua-api.lua`](lua-api.lua): Lua request tables use the serialized names, which are usually `camelCase`, while enum values are explicitly snake_case, kebab-case or lowercase as documented.

## Documentation and contract maintenance

`docs/lua-api.lua` is generated from the typed registry and runtime namespace inventory. After changing an editor Lua method, event, host operation or contract type, regenerate it with `cargo run -p neoism-lua --example generate-lua-api > docs/lua-api.lua` and run `cargo test -p neoism-lua --features runtime checked_in_lua_annotations_match_the_registry_generator`. Runtime-surface tests also reject an exported namespace missing from the generated reference and a registered action missing from `neoism.contract.platform.hostOperations`.

Agent HTTP contract maintenance uses `bash neoism-agent/scripts/openapi.sh check` or `npm run contract:check` from `neoism-agent/sdk/typescript`. Process and native contract changes should run the `process_v2_wire` and `plugin_conformance` tests documented in [`agent-plugins.md`](agent-plugins.md). Public examples must deserialize through both shared-package readers and must not rely on ignored unknown fields.
