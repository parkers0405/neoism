# Neoism v0.7.149-nightly.20261111.7

This Rune nightly follows `20261111.6`, whose build was stopped in favour of this one; it includes that release's Windows fix.

## Changes

- The workspace moves only to a folder its daemon confirms it has. The home terminal owns the workspace's directory, and what its shell reported was taken on trust. An `ssh` or a container shell inside that terminal reports a folder of another machine, on macOS, Linux and Windows alike: the workspace was re-rooted there, and the file tree, notes and conversation list went empty with nothing able to run or send. The reported folder is now checked with the daemon first; one it does not have is refused and the workspace stays where it is.
- On Windows, a shell's own folder is read correctly. A shell reports it as a `file://` URL whose path reads `/C:/Users/me` (Git Bash says `/c/Users/me`): absolute, but not a folder the Windows daemon can open. Those spellings are now read as the drive path they name, and the same folder spelled another way no longer counts as a move.
- The filesystem root (`/`) is kept as a workspace root instead of being trimmed to an empty path.

## Validation

The Rune app's 377 tests pass at this commit, covering the Windows spellings, a refused folder, a confirmed one and the root. In a real window on Linux, `cd` in the home terminal was confirmed by the daemon and the workspace followed. Nothing here was run on Windows or macOS: the Windows machine that reported the empty panels could not be reached, and on macOS no cause has been reproduced. The daemon check is the part that applies to macOS (it removes every way a reported folder can empty the workspace); whether it is what that report was is not known. The macOS and Windows builds are gated by CI only.
