Deep audit/fix for subagents appearing ~45s after returning to a workspace and completed historical children resurrecting active. Root causes: (1) desktop returning to an already-hydrated Agent route did not force runtime/tree reconciliation, so a missed lifecycle edge waited for the 40/45s watchdog; (2) `session.subtask.completed` lacked execution/family revision, so delayed outstanding snapshots could reopen completed children and delayed completions could terminate genuine continuations; (3) daemon upstream SSE was one-shot and synthesized SessionIdle on transport loss; browser visibility had no Agent resume barrier. Fixes: desktop `reconcile_after_activation` marks child tree dirty, forces runtime/status hydration, and idempotently keeps the existing root-family stream; server completion payload now includes rootSessionID/executionID/familyRevision; desktop/shared panes keep per-child terminal revision floors and gate both delayed active snapshots and delayed terminal events while allowing strictly newer continuation; protocol/daemon/WASM carry fields; daemon SSE reconnects with 250ms..5s backoff, 45s no-byte timeout, runtime/status snapshot after reconnect, no fake idle, and exits when tx closes; browser visibility sends idempotent ResumeStream and disposes listeners on bridge replacement. Sidebar child clicks still use the same root-family stream and were not rebound or stopped. OpenCode v2 avoids much of this by treating durable parentID + Task metadata as the primary child projection and ordering global bus events; Neoism's richer execution_subtasks projection requires all lifecycle evidence in the family revision domain. Verified native stack cargo checks, wasm check, web tsc, protocol 92 tests, OpenAPI 9 tests, focused shared/desktop revision races, daemon terminal mapping, viewed-child parent continuation, hidden-pane drain, and legitimate continuation. Full daemon integration test compilation remains blocked by pre-existing AppState missing lsp_runtime in multiple tests.
