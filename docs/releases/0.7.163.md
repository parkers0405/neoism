# Neoism v0.7.163

This stable release makes the Agent's transcript calmer with a focused view of each turn, adds an option to open a sent message at the top, and refreshes the chat font and the activity rail, on Linux, macOS, and Windows.

## Focused Agent view

- While a turn runs, it shows the Agent's notes as they are written and, between them, its tool calls as one quiet line each: an icon and the call's name. Only the newest five of a run are listed; the rest are counted as "earlier steps".
- When the turn is done, all of that folds under one work row, such as "Worked · 14 steps · 3 files changed", with failures counted in red. The reply stays in view.
- Pressing the work row opens that turn as the full trace of cards and diffs, held in place under the pointer. Older turns fold and open the same way.
- A sub-agent that is still working keeps its card until it finishes. Checklists, your own shell commands and notices always show.
- The running turn's activity line names the step it is on after its timer.
- Settings > Agent > **Focused agent view** turns it off, and every call is a card again. It is on by default.

## Send to top

- Settings > Agent > **Send to top** (off by default) opens each sent message near the top of the view, with the reply streaming into the room below it.
- A turn that runs tools or reasons is followed as before. A reply of text alone keeps its start in view; jump-to-latest follows it. Scrolling takes over at once.

## Look

- Chat text defaults to the platform's own interface font: San Francisco on macOS and Segoe UI on Windows, with Geist as the fallback and the default on Linux. Settings > Appearance > **Chat font family** still changes it.
- The activity rail uses drawn line icons for files, notes, agent, servers and settings.
- Tab titles use the proportional interface font. A tab shows an accent dot while its agent is working and a yellow dot for an unsaved file.

## Validation and downloads

Linux x86_64, macOS Apple Silicon, and Windows x86_64 build, test, and package independently from the same immutable stable tag. The daemon image uses the same tagged source. Local checks, publication and checksum verification are reported separately; this is not a claim of manual GUI testing on every platform. The macOS bundle is signed with a Developer ID and publishes only if Apple notarizes it.
