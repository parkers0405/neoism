**Symptom:** a guest who joins a hosted workspace (Create-Server flow) whose served repo has a live dev stack (synapse-ai-hub: Next.js/api/worker docker) gets ~4fps and system-wide slowness. Host that stays local feels fine; MD-file-open made no difference (ruled out CRDT/editor plane).

**Root cause:** `neoism-workspace-daemon/src/fs_watch.rs` puts a `RecursiveMode::Recursive` notify watch on the whole served root (measured 19,181 inotify watches on synapse) with **no ignore list**. The dev stack continuously touches `node_modules` and `.git`, so the daemon broadcast ~3.3 `FilesReply::Changed` bursts/sec (each capped at 64 paths: ~53% node_modules, ~27% .git, ~20% source). The desktop client (`file_tree/daemon_sync.rs` `Changed` arm) does a `relist_open_dirs()` + `start_remote_git_status_refresh()` per burst; a `.git` path in a burst always sets `git_relevant`. DEBOUNCE = 300ms → 3.3 bursts/sec → one relist+git-status per ~300ms → **4fps** (the cadence literally sets the frame rate). Both host (joined to own server for multiplayer) and guest fed it.

**Diagnosis method (remote, no Mac access needed):** subscribed to the same daemon `ws://…/session` as a passive client and histogrammed the broadcast — the Mac receives the same stream. Scripts in scratchpad: `stream_probe.py` (variant histogram), `burst_dump.py` (path buckets + .git-per-burst), `burst_diff.py` (overlap = churn vs re-report). Gotcha: `inotifywait -r` on 19k dirs takes >14s to arm watches — all "inotify sees nothing" readings were invalid (tool never finished setup); the daemon armed once at startup so it DID see real churn. Confirm daemon watch count: `grep -c '^inotify' /proc/<daemon-pid>/fdinfo/<inotify-fd>`.

**Fix (landed, cargo-checked, on branch better_workspace):** added `IGNORED_SEGMENTS` + `is_ignored_watch_path(root, path)` to fs_watch.rs and filter in the watcher callback before `event_tx.send`. Drops `.git`, `node_modules`, `target`, `dist`, `build`, `out`, `.next`, `.nuxt`, `.svelte-kit`, `.output`, `.vite`, `.turbo`, `.parcel-cache`, `.cache`, `__pycache__`, `.venv`/`venv`, `.mypy_cache`, `.pytest_cache`, `.ruff_cache`, `.tox`, `.gradle`, `.idea`, `vendor`, `.terraform`, `coverage`, `.nyc_output`. Match is component-wise on the path RELATIVE to root (root's own ancestors named like an ignored dir don't disqualify; `dist.rs` kept, `dist/x` dropped). `.git` dropped wholesale — worktree edits still fire and drive git-badge refresh; only a bare branch-flip with no worktree change goes unsignalled (guest re-lists on focus). Requires daemon rebuild + restart of the Create-Server flow to take effect.

**Follow-ups:** (1) still HOLDS 19k watches (only broadcast is filtered) — a `NonRecursive` manual descent that skips arming under ignored dirs would cut watch count + host CPU; (2) client-side git-refresh debounce as defense-in-depth for rapid *source* churn; (3) the two pre-existing daemon integration-test failures (`tests/remote_pty_io.rs` SessionCwd, `tests/presence_ws.rs` CrdtPeerPresence{insert,rainbow}) are from other in-flight work, not this fix.
