# Neoism v0.7.149-nightly.20261110.3

The third Rune nightly, from a day of using the first two. Stable remains on v0.7.148.

## Changes

- Hosting a folder opens a workspace in that folder with a working terminal (it opened on `~` with no shell); the same held for an SSH system's home workspace. A shell that fails to start asks again instead of leaving its tab waiting, and a failed host shows the daemon's own reason.
- Sub-agents: listed under their conversation in the sidebar while they work and for a moment after, on a connecting line with their status; opened in the conversation's own tab, in place, with their history already fetched; one event stream per family; the activity line while one works and no input bar in its conversation; finished in the sidebar and on its task card as soon as it stops. A running conversation turns a loader in its row.
- Old turns stay answer-only: loading older history no longer exposes the tool calls and thinking of finished turns. Thinking stays ahead of the reply it precedes.
- Background tasks show their own line under the transcript.
- A chat table's scroll bar clears the input bar and shows while the wheel turns over the table; links in table cells open; tool cards that open show the hand.
- The input bar's stars stay inside the card and twinkle.
- On a cold start the conversation list is asked for again once the agent service is up.
- `exit` in a Home terminal closes its tab; close buttons are red; the mode pill settles on its last frame.
- A crash is written to `$XDG_STATE_HOME/neoism/crash.log` (or `~/.local/state/neoism/crash.log`) with the build and the stack.
- A restored window never reopens in a launcher's folder. The first workspace opens in the home folder when the app is started from the Dock, Finder or the Start menu, and in the folder named by `--working-dir` or a path argument otherwise.

## Known gaps

- The macOS title band and Option-as-Alt, and the Windows caption buttons, follow the toolkit's documented behaviour and have not been confirmed on those systems by a person. The Windows build has not been used by a person at all.
- Sub-agent behaviour is covered by tests against the daemon's event shapes and a staged scene, not yet by a recorded live run. A reported crash while hosting was not reproduced.

## Build provenance

The immutable release tag identifies the initial source snapshot. Platform bundles include `build-info.json` with their exact source commit, version, platform, and architecture; Windows bundles also record service hashes. Any necessary platform-specific retry uses an exact source commit without moving the tag or rebuilding successful platforms. Published payloads have SHA-256 sidecars.
