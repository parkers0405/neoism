Windows Host (ordinary and Fast) calls standalone::run -> agent_hosting::associate -> server::mint_agent_credential -> POST /v2/hosting/associate BEFORE readiness/advertisement. Desktop embedded_daemon.rs and Agent caller.rs use %TEMP%/neoism-<sanitized USERNAME>/daemon-token; daemon_token.rs incorrectly used dirs::data_dir()/neoism-daemon/daemon-token (%APPDATA%). If absent, signer falls back to hosted NEOISM_DAEMON_TOKEN (ordinary password or Fast random private master), which shared Agent rejects with HTTP401 code auth.invalid_token, message invalid daemon credential signature. User confirmed joining both kinds works and only Windows hosting fails; joining does not use this local startup association. Source fix in daemon_token.rs aligns Windows to desktop/Agent temp path; tests cover username sanitization/default/path wiring; Unix-specific XDG/mode bootstrap tests cfg(unix) to avoid Windows compilation failure and touching real token. No client/transport/auth relaxation edits. Existing %TEMP%/neoism-Piss/daemon-token observed by directory listing; %APPDATA%/neoism-daemon contained audit.log only (no token). No secrets read. LocalAppData/neoism/log/workspace-service.log shows Windows embedded loopback TCP7878 and successful Hello, no retained signature/hosting failures. Ordinary startup diagnostics go to anonymous tempfile and Fast to captured in-memory redacted tails, so no log absence proof. Hosted-servers/9877 empty consistent with no successful metadata commit, not conclusive. Working tree initially clean. Verification: git diff --check passed. Cargo installed ~/.cargo/bin but absent from PATH; prepended for checks. Online checks downloaded dependencies but exceeded bounded timeouts; final cargo check --offline -p neoism-workspace-daemon --lib --tests began dependency compilation and timed out after 180s, no Rust diagnostic observed but target NOT verified. No release build/tests run, no live hosting reproduction or installed binary replacement. Tailscale/SSH investigation delegated to parent. Compatibility note: no old roaming token exists on this machine; path change does not migrate any old standalone-only roaming token. Ordinary hosting without password inherits the desktop key and may already work when old roaming token absent; the failure mechanism is strongest for ordinary hosting with password and Fast Host (always a separate private master).
