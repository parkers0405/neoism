# Artifact theme contract (published for engine integration)

Public exports from `neoism_interactive_artifacts`: `ArtifactStyles`, `ArtifactColors`, `StyleError`. `ArtifactDocument` gains **`pub styles: ArtifactStyles`** (required on wire; no serde default). Its existing `theme: Theme` and source `revision` remain unchanged.

`ArtifactStyles { pub colors: ArtifactColors, pub font_sans: String, pub font_mono: String, pub radius: f32 }` is a small fixed typed snapshot. Colors are 24-bit RGB `u32`; font fields are plain single-family names (not CSS fragments); radius is CSS pixels. `validate(&self) -> Result<(), StyleError>` rejects invalid RGB, empty/oversize/control-containing fonts, and nonfinite/out-of-range radii. `css_variables(&self) -> Result<BTreeMap<String, String>, StyleError>` validates then produces safe CSS values. Hex RGB colors use `#rrggbb`, font stacks are CSS-escaped quoted family + generic fallback, radius uses `px`.

`ArtifactColors` public RGB fields: `background`, `foreground`, `card`, `card_foreground`, `popover`, `popover_foreground`, `muted`, `muted_foreground`, `border`, `input`, `primary`, `primary_foreground`, `accent`, `accent_foreground`, `destructive`, `destructive_foreground`, `success`, `warning`, `info`, `chart_1` through `chart_6`. These map to the standard `--background`, `--foreground`, `--card`, `--card-foreground`, etc.; charts map to `--chart-1` through `--chart-6`. Also emitted: `--font-sans`, `--font-mono`, `--radius`. No redundant namespace aliases.

All three types serialize/deserialize under the existing optional `ipc` feature, without a Servo dependency. `ArtifactDocument::validate` validates styles and returns `Error::InvalidStyles(StyleError)` for invalid snapshots. Unknown style/color fields are rejected during IPC deserialization. Font names are limited to 256 UTF-8 bytes with no control characters; radius must be finite and within 0–64 CSS pixels. Validation/escaping is an injection precaution, not sandboxing or a privileged bridge.

**Engine expectation:** on reconcile, compare the entire `styles` snapshot independently of `revision`. Apply its CSS variables to the current document root and invalidate paint **without navigation/reload**. Theme, styles, viewport, and visibility updates must preserve source revision and JS state. Install the initial snapshot before running author code to avoid a flash of the wrong theme. Engine agent owns the bootstrap/root-style update mechanism; desktop does not call arbitrary JS.

Desktop mapping uses the actual `renderer.styled_theme(AGENT_CHAT)` snapshot (including Lua overrides) plus currently selected renderer/config font names. Desktop updates retained hidden views too, and stores the full snapshot in each slot. Source revision changes only when HTML changes.
