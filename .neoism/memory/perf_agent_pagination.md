Making "load older" in the neoism-agent timeline (desktop `NeoismAgentPane`) fast and non-degrading. Symptom the user hit: each loaded page made it progressively slower, "re-rendering all older + viewport messages, keep going."

**THE per-frame tax (found via perf split, biggest single win):** `render_timeline_with`'s "prep" phase cost a FIXED ~1.5-2.4ms every frame regardless of message count. Split timers proved it was `clear_tool_hit_rects` → `self.selectable_lines.clear()`. The draw registered a `String` per visible line every frame (`register_selectable_line(text: String)` via `line.to_string()`), and the next frame's clear DROPPED/freed them all. ~1000+ alloc+free/frame; in DEBUG each free is slow → ~1.5ms. (The terminal renders 500k lines fine because it never allocs per-line-per-frame.) Fix: retain the `selectable_lines` Vec + its `String` allocations across frames — `register_selectable_line(text: &str)` reuses slots in place (`slot.0.clear(); push_str`), and "clear" just resets a `selectable_lines_len: usize`; all readers slice `[..selectable_lines_len]`. layout_us≈8µs, range_us≈3µs were never the problem; draw `rows_us`≈700µs (re-shaping + per-card `message.clone()` of text/detail — next target is `Arc<str>` + glyph caching). Perf gated on env `NEOISM_AGENT_UI_PERF_LOG`; the "agent timeline prep split" line logs metrics_us/set_metrics_us/clear_us/range_us.

Root causes found (in order of impact):
1. **Runaway load cascade** (the big one). After a page prepends, if it adds little height (tool groups collapse to few short rows) you're *still* near the top, so `maybe_request_older_timeline_page` re-fires every round-trip and pulls the whole transcript in within seconds — each fold/measure piling on. Fix: gate the trigger on real scroll activity (`timeline_last_scroll_at` recent OR `timeline_is_inertial()`) + a `timeline_last_older_request_at` cooldown (180ms). Parked at top = no auto-load.
2. **Blocking fetch on the UI thread** — `execute_load_older_timeline_command` did a sync 10s HTTP GET on the render thread. Moved to a background thread → `NeoismAgentBackgroundUpdate::OlderTimelineLoaded`.
3. **Full layout rebuild per prepend** — `invalidate_timeline_layout()` rebuilt all rows. Added incremental fold `prepend_timeline_layout` in shared `view/timeline.rs` (lays out only new prefix, shifts existing rows by delta, converges at a matching edit-tool boundary; full-rebuild fallback). Gated via `take_timeline_prepend()`. Was being skipped whenever `dirty` marks existed (i.e. while streaming) — removed that gate; now folds then patches the shifted dirty tail.
4. **Per-frame O(total) wasted Vec** — `timeline_virtual_row_measurements` built every frame even on desktop where `sync_virtual_timeline` is a no-op. Gated behind `uses_virtual_timeline()` (desktop=false).
5. **Cache cliffs** — height measure cache wholesale-`clear()`d at 2048 (→16384); markdown blocks cache 512 (→4096, LRU).
6. **Server loaded whole session per page** — `list_messages_page` now pushes cursor+limit into SQL (`message_position` resolves cursor by message-id PK then a `message_json LIKE '%"id":"<cur>"%'` fallback for part-id cursors).

Cursor matching gotcha: client blocks key user messages by `info.id` but assistant blocks by part id — the server must match both or pagination silently stalls.

**Still eager, not yet done:** every page still *measures* all ~128 loaded messages (mostly off-screen) on the UI thread. The gold-standard next step is viewport-only/lazy measurement. Key insight that makes it safe: scroll is distance-from-bottom, so off-screen-above height estimate errors cancel in `card_y = y + row.top - scroll_top` (both carry the same cumulative error) — visible content doesn't jump; only the scrollbar adjusts. Measure a buffer above the viewport so rows are exact before they enter. User constraint: do NOT regress the scroll that "feels amazing" at low message counts. See [[project_markdown_editor]] for the editor's true-virtualization reference.

**"Slows down after 3-4 questions" regression (2026-07-08, deep-trace):** the draw loop (windowed via `partition_point`), per-frame hit-rect/selectable buffers (cleared/reused), and the markdown cache key (stable: text_hash+len+width+scale, no time/tick) are all FINE — ruled out. Real causes: (§4, primary) `AgentSessionUpdate::Messages` full-snapshot handler (`pane/ingest.rs:22`) called `invalidate_timeline_layout()` on ANY diff → dropped the whole layout cache → next frame did an O(total transcript) rebuild that re-hashes full text of every message (`append_timeline_rows` 0..source_len + `layout_assistant_markdown_cached` full `hash_value(&text)`); snapshots arrive around every turn so cost grew per question. FIX: diff the snapshot — same count → `mark_timeline_message_dirty_at` only differing indices (patch), structural change → full invalidate. (§6) `running_background_task_count` (`pane.rs:1152`) ran every frame via `has_status_activity()` (`render.rs:40`), iterating all messages twice + allocating two BTreeSets even idle. FIX: cheap `any(running background_task)` fast path returns 0 with no alloc. Still-open follow-ups the trace flagged: desktop pane still on the eager full-history path (`uses_virtual_timeline()=false` — only the web pane implements viewport-only `sync_virtual_timeline`); `build_timeline_layout_pages` runs O(rows) on every patch/prepend; `mark_animating_tool_rows_dirty` iterates all messages per frame while a tool-expand animates; `dirty_start_source` is O(n) per dirty id.

Pre-existing broken tests (NOT mine): `compact_session_queues_outbound_command_for_runtime`, `history_refresh_keeps_compaction_marker_in_original_slot`, server `compacted_summary_trims_messages_already_covered_by_summary`, `prompt_persists_streamed_assistant_message`.

**Lazy/viewport-only measurement — SHIPPED (2026-07-08, flag-gated).** Env `NEOISM_AGENT_LAZY_TIMELINE` (read once via `lazy_timeline_enabled()`; absent on wasm → web stays eager); trait default `timeline_lazy_measurement()`. Contained entirely in `view/timeline.rs` (flag+cache field) + `view/timeline/layout.rs` (build path) + `render.rs` (passes `viewport_h` into `timeline_layout`). Design: only the FULL rebuild (`build_timeline_layout`) goes windowed — `build_lazy_rows` estimates every row cheaply (`estimate_message_height`, deliberately under-counts rich content → exact region only grows = safe) to locate the window, keeps the off-screen prefix estimated (markdown None), then rebuilds the on-screen suffix (from ~2×viewport above the viewport down to the end) via the PROVEN `append_timeline_rows` so grouping/skip/measure is identical. Correct because scroll is distance-from-bottom (`scroll_top = content_h - viewport_h - offset`, render.rs:94) so the estimated-prefix error cancels in `card_y = y + row.top - scroll_top` for visible rows; only the scrollbar thumb is approximate. Streaming (dirty-tail patch) + pagination (prepend gated off when lazy → cheap full lazy rebuild) unaffected. Rebuild-before-visible trigger lives in `timeline_layout`'s cache-reuse filter (`lazy_cache_covers_viewport`): drop the cache once the viewport scrolls within one viewport of the exact-region top. Cache carries `estimated_prefix_rows` (0 on eager/web/round-trip). Default OFF so the low-count scroll feel is untouched; desktop app + shared lib compile clean.
