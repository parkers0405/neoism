**2026-07-27 Windows parity wave** (supersedes the guard-only state in [[project-mac-win-builds]]): the whole stack now has real Windows implementations, compile-verified on `x86_64-pc-windows-msvc` locally.

**Local Windows build loop (works on the arch box):** `env -u CI cargo xwin check --target x86_64-pc-windows-msvc -p neoism -p neoism-workspace-daemon -p neoism-agent --features wgpu` — cargo-xwin + system clang/llvm-lib/llvm-rc; SDK cache ~1.6GB in `~/.cache/cargo-xwin`; full check ~2min warm. C deps (ring/libgit2/tree-sitter) all cross-compile fine. Wine not installed (needs sudo). Real-runtime lane = `gh workflow run build-mac-win.yml -f only=windows` (now runs ConPTY tests + daemon-boot smoke + packages a zip).

**Key architecture decisions:**
- Embedded daemon on Windows = loopback TCP primary listener on `default_tcp_port()` (7878, `NEOISM_DAEMON_TCP_PORT` override; port-bind AddrInUse doubles as the single-instance guard). `EmbeddedDaemonHandle::client_url()` returns `unix://` or `ws://127.0.0.1:{port}/session` per platform. `resolve_daemon` is universal (probe socket / probe TCP → attach, else spawn). Accept loop refactored to one task per listener (no more unix-shaped select!).
- Agent PTY tool (`pty_process.rs`) = real ConPTY: `PtyChild` enum (tokio `Spawned` vs raw `Conpty`), conin/conout as `tokio::fs::File`, `ResizePseudoConsole`, kill = Toolhelp tree-kill children-first then `TerminateProcess` then `ClosePseudoConsole` (which is REQUIRED after exit or the reader never EOFs; BrokenPipe = EOF). Pipe path kept only as pre-1809 fallback.
- Windows cwd inference (tab-in-cwd, workspace re-root, title paths): the OSC 7 `terminal.current_directory` is the source — there is no /proc cwd and exe-path is NOT cwd. `foreground_process_path` on Windows returns the exe image path (different semantics from unix's cwd!).
- Agent dirs on Windows all nest under `%USERPROFILE%\AppData\Local\neoism` (state/, cache/) matching neoism-backend `config_dir_path()`; `NEOISM_AGENT_CONFIG_DIR` keeps absolute precedence.
- Single-instance IPC = named pipe `\\.\pipe\neoism-command-<user>`, same wire format; `NEOISM_IPC_SOCKET` overrides the pipe name.

**Wine runtime lane (proven 2026-07-27, no sudo needed):** `nix build nixpkgs#wineWow64Packages.minimal` → wine-11.0; `WINEPREFIX=<scratch> WINEDEBUG=-all CARGO_TARGET_X86_64_PC_WINDOWS_MSVC_RUNNER=<wine> env -u CI -u NEOISM_DAEMON_TOKEN cargo xwin test --target x86_64-pc-windows-msvc -p <crate>`. Validated: daemon boots ~1s under Wine (AppData paths, token mint, ACL warn-and-continue, HTTP 404s, AddrInUse vs the LIVE linux daemon on shared loopback 7878 — use NEOISM_DAEMON_ADDR=127.0.0.1:7979); all teletypewriter/pty tests incl. real ConPTY spawn pass. **Found+fixed 1 real bug this way:** agent-server conpty::spawn was missing `STARTF_USESTDHANDLES` (null handles) → child bound the parent console instead of the pseudoconsole (no output); also console-side pipe ends must close AFTER CreateProcessW (EchoCon ordering — Wine doesn't duplicate them at CreatePseudoConsole like real Windows). Test-design rule: sync-pipe ConPTY reads MUST have a concurrent thread closing the console on child-exit (production monitor does; a same-thread try_wait/read loop deadlocks). GOTCHA: the dev shell exports NEOISM_DAEMON_TOKEN (64 chars) — daemon then never writes a token file by design; unset it when testing minting.

**Gotchas learned:** windows-sys 0.60 `HANDLE` is `*mut c_void` (use `.is_null()`, not `== 0`); `creation_flags` on Command REPLACES flags (single-site rule); tokio can't attach a pseudoconsole attribute — ConPTY needs raw `CreateProcessW`; tree-sitter grammars are statically linked (the ".dll parser bundle" concern in old memories was never real).
