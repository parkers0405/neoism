Two compaction bugs in neoism-agent (`session_context.rs` + `session_prompt.rs`), fixed to match opencode's golden behavior (`opencode/packages/opencode/src/session/{compaction,overflow,revert}.ts`).

**1. Auto-compaction looped / "glitched the crap out".** `summary_covers_all_messages` (the anti-recompaction guard) reads `info.extra["summary"]["throughMessageID"]`, but compaction NEVER wrote that field — so the guard always returned false and the auto-compactor re-summarized the same state repeatedly. Compounded by: `maybe_auto_compact_before_step` compacts but the caller never refreshed `history`, so `provider_messages_for_session` rebuilt from the stale *pre-compaction* full conversation and immediately tripped a second compaction. Fixes: (a) write `"throughMessageID": assistant_message_id` (the compaction summary message, now the store tail) into the summary payload; (b) refresh `history` right after `maybe_auto_compact_before_step` when it compacted; (c) guard BOTH `should_auto_compact_provider_prompt` sites (pre-first-step and in the followup loop) with `!summary_covers_all_messages(&info, &history)`. opencode avoids this structurally: compaction always reduces to summary + bounded tail (DEFAULT_TAIL_TURNS=2, ≤clamp(usable*0.25,2k,8k) tokens) and `isOverflow` checks the last assistant's ACTUAL tokens.

**2. Manual /compact stuck ~50s then "... earlier context truncated during local compaction".** That string is the LOCAL fallback `build_session_summary` (16k-char truncation), hit when `generate_model_compaction_summary` returns `None`. Root fragility: `append_compaction_text_delta` `?`-propagated any store error mid-stream, discarding the whole model summary → fallback. Fix: per-delta persistence is now best-effort (errors logged/ignored, never aborts); the full summary is still written once at the end by `finish_compaction_assistant_message` (which SETS, not appends, text). The fallback now only fires on a genuine model/stream failure.

**3. "Compaction · summary" divider shows but NO summary, session bricked (2026-07-06, openai/gpt-5.5 high).** The summarize REQUEST itself overflowed → `generate_model_compaction_summary` → None → `compact_session_context_inner` returns `Err` → the four `maybe_auto_compact_*` sites `?`-propagated it and killed the run; every later prompt re-fired the same failing compaction = permanent stuck. TWO independent triggers, same None: (A) unbounded replay — the WHOLE session (incl. 20KB-per-tool-output via `COMPACTION_TOOL_OUTPUT_MAX_CHARS = 20*1024`) was fed into the summarize request while already near the limit; (B) `model_compaction_timeout_secs()` was 60s *inter-event* — a high-reasoning model thinks >60s before the first delta → `Err(_) if raw.trim().is_empty() => return None`. Fixes in `session_context.rs`/`message_model.rs`/`session_prompt.rs`, matching opencode `compaction.ts` `select()`+`TOOL_OUTPUT_MAX_CHARS`: (a) `COMPACTION_TOOL_OUTPUT_MAX_CHARS` 20*1024 → **2_000** (opencode parity); (b) summarize only the HEAD via new `compaction_head_messages` (messages since last completed compaction, minus the protected tail that stays raw post-compaction) + re-anchor the previous summary via `compaction_request_prompt` (`<previous-summary>…</previous-summary>` + template) instead of replaying old raw context; (c) budget-trim the head (`compaction_request_token_budget` = usable-context × 3/4) dropping oldest head msgs until it fits; (d) timeout 60 → **240s**; (e) ALL FOUR compaction call sites now `match { Ok/Err→tracing::warn + continue uncompacted }` — a failed compaction can NEVER brick the run again. New tests: `compaction_head_excludes_protected_tail`, `_falls_back_when_tail_swallows_everything`, `compaction_request_prompt_anchors_previous_summary`. Note: `session_id: None` field was missing from ~9 test-only `ProviderGenerationRequest {}` initializers in `provider_transform.rs`/`provider_anthropic.rs` — pre-existing test-target breakage, fixed in passing.

Pre-existing failures (NOT compaction, verified 2026-07-06): (1) `tests::compacted_summary_trims_messages_already_covered_by_summary` — STALE test, sets summary only in `info.extra` with no marker message; real code sources it from the marker MESSAGE (`session_summary_message`). (2) `tests::prompt_persists_streamed_assistant_message` — resolves provider `openai` not `neoism` from a models catalog at session creation; no compaction runs in that single-message test. Both fail independent of my changes. See [[bug-agent-edit-lsp-freeze]].
