The md editor lives in `neoism-frontend/shared/src/editor/markdown/`. The **virtualized** renderer (`render/virtualized.rs`, ~3200 lines) is the active path (`render/mod.rs:59` dispatches to `render_virtual`); `render/mod.rs` also holds an older renderer still used in places.

Core gotcha: **rendered text ≠ raw buffer**. The cursor is a raw byte `cursor_col`, but the renderer draws *cleaned* text (inline markers `*`/`` ` ``/`**` hidden, whitespace collapsed). Caret X is computed by cleaning the prefix and measuring it, so any mismatch between the cleaning and the render drifts the caret.

Key pieces:
- `render/inline.rs::strip_inline_markers` must mirror `virtualized.rs::inline_marker_at`/`inline_runs_for_text` — only hide *closed* markers (fixed: unclosed `*` while typing used to be dropped → caret drift).
- Two parallel wrappers exist: `inline_wrapped_lines` (render) vs `draw.rs::wrap_lines`+`normalize_wrapped_text` (caret) — they can disagree on wrapping/whitespace.
- Literal interior spaces preserved via `InlineWord::lead_ws` (only applied when word isn't first on its visual line, so wrap-continuation stays flush).
- Vertical nav uses a monospace `max_chars` grid (`navigation.rs::visual_metrics_for_line`) while body text is proportional; accurate per-visual-row data exists in `block_wrap_rows` (used by click hit-test, not yet by nav). Sticky goal column = `goal_visual_col`, cleared in `clamp_cursor` (universal chokepoint), round-tripped by `move_up`/`move_down`.
- Marker/checkbox vertical centering uses `render/bullet_align.rs` (x-height ratio 0.52); center against the **17px body** font, not the 16px marker font.
- **Heading NODE classification trims, renderers must too**: sugarloaf's adapter `heading_level` trims leading ws, so "  ### x" IS a Heading node — computing level via untrimmed `take_while('#')` reads 0 hashes and `.clamp(1,6)` silently says h1 (giant heading w/ raw hashes when user types Tab/space before `###`). Use `heading_node_level_and_marker` (draw_blocks.rs).
- **"Virtual spacing" root cause (took 3 angry rounds)**: `widgets/markdown.rs::wrap_words_measured` split the *trimmed* token instead of the token, so `ws` was always empty — every whitespace run collapsed to the `.max(1)` floor. Drawn heading rows were SHORTER than source → caret (real source chars) slid onto the next word while no gap appeared. Headings draw whole-row strings through this wrapper; body lines use `inline_wrapped_lines` (separate, was fine). When caret and glyphs disagree, diff the ROW TEXT length against the source slice first.
- Measurement is cursor-aware: `MarkdownVirtualMeasureKey.cursor_token` + `measured_cursor_line` dirty-marking in surface.rs (revealed line wraps differently → re-measure nodes cursor leaves/enters same-frame).
- Frontmatter (`---` pair at line 0) renders as Notion properties (draw-side only, heights match measure's divider/paragraph rows); `title:` key feeds the inline title drawn in render_virtual. Quotes (`> `) render styled (accent bar + italic, marker hidden) except cursor line.
- **User mandate: tables must be edited WHILE RENDERED — never reveal raw table source** ("editing raw markdown tables is gross"). Table improvement plan = focused-cell editing inside the rendered grid, Tab/Shift+Tab cell hop, per-cell measured stops, column resize.

- **Invalidation gotcha (zoom overlap bug, 3 rounds to find):** bumping `virtual_render.source_revision` does NOT rebuild when the source text is identical — `prepare_surface` takes an empty `for_route` batch fast path that keeps old measured layouts, and `commit_visible_measurements` skips any item with `measured_layout` (`visual_line_count > 0`). To force re-measure (e.g. font-scale change), apply `VirtualSurfaceCommand::MarkRangeDirty{0..nodes.len(), DirtyKind::Layout}` — `resolve_dirty_layout` resets layouts to estimates (`visual_line_count = 0`) and the visible set re-measures same-frame. Symptom signature: wrong layout that self-heals on tab switch (pane recreation = real rebuild).

See [[feedback_keep_building]] — user runs the build themselves; verify precision/visual md fixes with their eyes.

## MD editor perf (2026-07-08 deep-trace)
Ruled out (already fine): scroll/idle per-frame (HeightIndex O(log n+visible)), measurement/wrap caches (viewport-bounded, not cleared per edit), per-line tree-sitter highlight cache. The two O(document) **per-keystroke** costs, both gated only by the 20k-line/2MB "large" threshold:
- **#1 (dominant, NOT yet fixed):** a middle-of-line edit falls through `prepare_surface` (`render/virtualized/surface.rs:777-833`) to `build_replace_batch` → `markdown_nodes(whole text)` + `ReplaceAll` + full layout/height rebuild. Only tail typing is incremental. The **large-doc path already IS incremental** (`prepare_large_line_surface`, `node_for_line`+`build_existing_line_node_update_batch`, incl. a `same_line_count` case ~line 1082). Fix = give normal-size single-line edits that same path, guarded conservatively (block-signature unchanged → re-parse containing block; sig change/fence → fall back to `build_replace_batch`). Normal path recomputes `line_starts` fresh each frame (line 781) so no staleness there. Risk = node-structure compat between `markdown_nodes` vs `build_replace_batch_from_lines` + rendered-content correctness → needs RUNTIME verification (type in a file, watch render), not just cargo check.
- **#2 (FIXED):** `rebuild_blocks` (`history.rs`) re-joined+re-parsed the whole doc on every edit — but `blocks` is read only on load/reload (title) + a CRDT test; the outline reads `lines` not `blocks`. So per-keystroke parse was pure waste. Now `rebuild_blocks` just marks `blocks_dirty`+bumps source_revision; `ensure_blocks()` re-parses lazily; `set_source`/reload call it before the title read. Field `blocks_dirty` on `MarkdownPane` (types.rs). Desktop app + shared lib compile clean; `--tests` targets pre-existing-broken (PaneFocusDir, scroll_model/tests, private methods — unrelated).

## MD editor #1 — SHIPPED (2026-07-08): incremental middle-of-line edits
The dominant per-keystroke cost (full `build_replace_batch` reparse for any non-tail edit) now has a fast path in `render/virtualized/surface.rs prepare_surface`: for a single in-place line edit it re-parses only the edited line's node via `build_existing_line_node_update_batch` (the SAME incremental update the large-doc path uses), else falls back to the full rebuild. Guard = pure `single_line_edit_target()` (no adapter mutation, so fallback stays clean): same line count; cursor line actually changed AND is the only change (whole-source byte delta == that line's delta); neither old nor new line is a fence (```/~~~); unchanged `structural_prefix` (leading whitespace + heading/list/quote/ordered marker). Those guarantee block boundaries can't move, so re-parsing just the containing node reproduces a full reparse (inline edits inside lists/tables/indented/fenced code stay correct; fences, marker/indent changes, blank-line merges take the full rebuild). Safe re: state because `apply_tail_inline_append` appends to the last line's END (never shifts a line-start), so `state.source`/`state.line_starts` stay consistent and the fast path only reads them for non-tail edits. Desktop app + shared lib compile clean. NOTE: still wants a live render check (type headings/lists/fences/tables and watch) — cargo-check only so far. #2 (deferred block reparse) already shipped separately.
