# Neoism v0.7.149-nightly.20261111.6

This Rune nightly follows `20261111.5`.

## Changes

- On Windows, the file tree, notes and conversation list no longer go empty a moment after the window opens, with no shell or prompt able to run. A shell reports its folder as a `file://` URL; on Windows the URL's path reads `/C:/Users/me` (Git Bash says `/c/Users/me`), which is absolute but is not a folder the Windows daemon can open. The home terminal owns the workspace's directory, so the workspace was re-rooted to that spelling as soon as the shell reported in. Those spellings are now read as the drive path they name (`C:\Users\me`), and the same folder spelled another way no longer counts as a move.

## Validation

The Rune app's 375 tests pass at this commit, including the path cases above and a workspace that stays put when its shell reports the same folder in URL form. This was found by reading the code after a report from a Windows machine that could not be reached to reproduce it: the fix has not been run on Windows, and whether it is the whole of that report is not known. The same report was made for macOS, where this cause does not apply; that one is still open. The macOS and Windows builds are gated by CI only.
