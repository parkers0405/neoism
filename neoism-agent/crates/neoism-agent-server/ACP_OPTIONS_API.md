# ACP root session options (backend API)

For a Neoism root created with `externalProvider: "opencode" | "codex" | "claude"`:

- `GET /v2/sessions/{id}/external/options` returns the last provider-confirmed ACP session options without launching another process when the root has a successfully replayed snapshot. After a replay failure, the saved choices and prior snapshot remain available on the root; an idle GET attempts to revalidate them. If replay still fails and an earlier provider-confirmed snapshot exists, GET returns that snapshot with `replayError` instead of treating its values as applied; the GUI exposes the model picker for recovery. On a new root it initializes ACP, may create one provider `session/new`, and persists its opaque `externalSessionId`; prompt and option changes still use `session/load` or negotiated `session/resume` and revalidate choices. It never sends Neoism's model selection to ACP.
- `POST /v2/sessions/{id}/external/options` accepts JSON `{"configId":"model","value":"provider-advertised-id"}`. The value must be an advertised `select` choice. The response is the complete provider-confirmed option state, including dependent updates. Unsupported IDs/values/types and incomplete provider responses fail; they are not silently accepted. Boolean options are not negotiated yet.

Both routes return JSON `{"provider":"opencode","configOptions":[...],"modeFallback":false,"selectedOptions":{"model":"provider-advertised-id"}}`. `configOptions` retains the provider's ordered ACP option objects, including `id`, `category` (`model`, `thought_level`, `mode`, `model_config`, or unknown), `type`, `currentValue`, flat or grouped `options`, and other provider metadata. Do not synthesize options in the GUI. `selectedOptions` are confirmed user choices saved on the Neoism root and reapplied to the next ACP process before prompting: replay applies a selected model first and then waits for conditional selectors (such as OpenCode Effort) to appear in the provider's complete response. Missing or rejected selections fail closed on prompts and GET; an explicit POST selecting a different model may replace a stale saved model, retaining only dependent choices confirmed after the change. `modeFallback: true` means the provider gave no config-mode option and the returned `mode` selector is derived from legacy ACP `modes`; setting it uses `session/set_mode`. Otherwise, selection uses `session/set_config_option` and its **full** `configOptions` response.


ACP v1 `available_commands_update` is a full replacement snapshot for the opaque `externalSessionId`. Both GET and POST options responses include `externalSessionId: string | null` and `availableCommands: [{name, description, input?: {hint}}]` alongside `provider`, `configOptions`, `modeFallback`, and `selectedOptions`. The same array is persisted at `session.extra.externalAgent.availableCommands` and delivered on `SESSION_UPDATED` (`{sessionID, info}`); an empty list clears it. Each new provider process clears the old snapshot before applying matching-session setup/replay/live updates, so a provider that stops advertising commands cannot leave stale entries. Malformed snapshots are rejected in full (maximum 256 unique slash-free names, bounded descriptions and input hints); wrong ACP session IDs are ignored. The GUI submits an advertised command as ordinary `session/prompt` text (`/name args`), never to Neoism's `/v2/.../commands` route. The list is provider-owned: absent updates mean no advertised commands, not a fabricated fallback.
`availableCommands` contains the ACP adapter's per-session `available_commands_update` entries; it is not a copy of the provider's TUI slash menu. OpenCode ACP additionally handles `/compact` in `session/prompt` even when it is not advertised, so the native picker exposes that verified special case without duplicating an advertised command. Other TUI-only actions are not represented as provider commands. A completed assistant message records the model selector's provider-confirmed `currentValue` at the end of its turn; this is a per-turn session selection, not proof of which internal model generated every token. When ACP provides no model selector, the message footer omits a model instead of substituting the provider name.

A `config_option_update` event replaces the current option snapshot only if it agrees with every explicitly selected option; load-time default notifications cannot overwrite confirmed choices. `SESSION_UPDATED` notifies subscribed GUI consumers without advancing the conversation's activity timestamp. POST, uncached GET, queued/running ACP prompts, and concurrent option requests return `409` when they would contend for the ACP session (retry when idle); a cached GET remains read-only. Routes require session authorization and a local-operator, host-local ACP root; hosted, workspace-scoped, foreign-host, and non-root sessions are rejected. Provider initialization/login failures are surfaced; these routes do not authenticate on the user's behalf.


ACP usage arrives through the existing `message.updated` event (`{sessionID, info}`): `info.tokens` has `total?: number`, `input`, `output`, `reasoning`, `cache: {read, write}`. A live update keeps `info.time.completed: null`; the final response writes the same fields to the durable assistant and its `step-finish` part. Input/output exclude cache/reasoning respectively in Neoism's token convention. Failure/abort preserves observed assistant tokens but marks `info.error`; it does not emit a successful completion. No context window, model limit, or cost is inferred from absent ACP metadata. Explicit nested tasks require `toolCallId` plus a prompt and `subagent_type` in `rawInput`; children carry `extra.externalAgent.parentToolCallId`, and unfinished tasks become `error` or `interrupted` instead of remaining running. A provider's generic thought or tool title never creates a child.
Historical tools/CLI credentials remain provider-owned. On process restart/reload, a requested option that the provider no longer advertises **fails the prompt** rather than using a different model/mode without notice.
