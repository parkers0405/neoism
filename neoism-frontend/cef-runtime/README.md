# Standalone Chromium artifact worker

This independent workspace links CEF 154.5.0, not the desktop dependency graph. It renders live Chromium windowless (OSR) documents and speaks the existing interactive-artifacts v2 bounded stdio protocol. Only this directory is owned by the worker implementation; desktop launch/build integration is maintained by the parent.

## Build and test (Linux)

```sh
cd neoism-frontend/cef-runtime
CEF_PATH="$HOME/.local/share/cef" cargo check
CEF_PATH="$HOME/.local/share/cef" cargo build
CEF_PATH="$HOME/.local/share/cef" LD_LIBRARY_PATH="$HOME/.local/share/cef" cargo test
CEF_PATH="$HOME/.local/share/cef" LD_LIBRARY_PATH="$HOME/.local/share/cef" python3 tests/live_worker.py
# Optional online check also loads and executes pinned Chart.js from jsDelivr:
NEOISM_CEF_NETWORK_SMOKE=1 CEF_PATH="$HOME/.local/share/cef" LD_LIBRARY_PATH="$HOME/.local/share/cef" python3 tests/live_worker.py
```

The final command keeps the sandbox enabled. On this machine it passes with user namespaces available and a user-owned 0755 `chrome-sandbox`; no sudo, setuid installation, or sandbox-disabling switch was required. The regression inspects Linux Chromium renderer descendants (zygote-fork argv can retain `--type=zygote`, so compositor thread identity is also checked): `Seccomp=2`, `NoNewPrivs=1`, and absence of `--no-sandbox`. This verifies those sandbox properties on this host, **not an audited hostile-content security boundary**. The browser broker and this CEF distribution's network utility are not equally sandboxed.

Only explicit inherited `NEOISM_CEF_NO_SANDBOX=1` adds `--no-sandbox` and sets `Settings.no_sandbox`. This mode prints a warning and is for trusted experimental fixtures only. Neither `--experimental` nor a failed initialization disables the sandbox. There is no automatic unsafe retry.

## Launch and resources

The worker accepts `--stdio` or the parent-compatible `--stdio --experimental`. Resolve runtime resources using `NEOISM_CEF_DIR`, then `CEF_PATH`, then resources beside the executable, then `~/.local/share/cef`. `resources.pak`, `icudtl.dat`, locale files, and CEF snapshot files must match the linked CEF distribution. Initialization uses explicit resource/locale settings. Each worker gets a private 0700 temporary root cache, avoiding Chromium singleton collisions and reuse of the user's browser profile; normal shutdown removes it. Individual views use separate nonpersistent request contexts.

`build.rs` embeds Linux `$ORIGIN` rpath so packaged `libcef.so` beside the worker requires no global loader environment. A development executable without adjacent libraries needs a **child-scoped** loader path; the parent launcher supplies it. Setting `CEF_PATH` alone at runtime does not instruct the ELF loader. The desktop's normal-debug auto-build/cache discovery is parent-owned, not implemented in this workspace.

CEF `execute_process` runs before browser-process IPC redirection. CEF subprocesses are dispatched as subprocesses, not pipe workers. Their stdin is `/dev/null`, stdout is stderr; the parent also replaces inherited stdin with `/dev/null` before initialization. Saved IPC descriptors are CLOEXEC. The original pipes are used only by the bounded control reader and binary/JSON writer. `Hello { version: 2 }` is required, native engine logs cannot enter protocol stdout, malformed controls produce `Fatal` and orderly browser closure.

## Rendering and lifecycle

- Each document incarnation has its own browser and callback state. A revision replacement closes the previous browser rather than navigating a shared callback state. Same revision with different HTML is rejected.
- Same-revision theme and visibility changes update existing nodes/CSS variables and dispatch `neoism-theme-changed`; counters, inputs, scroll, and JS state are not reset. Updates arriving during initial load are applied again after load completion.
- Every reconciliation/resize invalidates pending pixels and advances a callback epoch. Main-frame load completion, host theme/layout execution, and a two-rAF renderer round-trip gate publication; superseded acknowledgments are ignored. Painting must match the exact physical viewport. The real regression checks **every** frame in tested generations, not merely eventual good pixels, including rapid theme pairs and legitimate white content.
- CEF BGRA premultiplied buffers become tightly packed top-down RGBA premultiplied buffers by swapping B/R only. Native SELECT dropdowns use `on_popup_show`/`on_popup_size`/POPUP paint callbacks: a separately retained popup is source-over composited onto the current retained VIEW, clipped to viewport bounds, including negative popup origins. Hiding restores the untouched base immediately. Reconciliation/resize clears both buffers and dismisses any open native popup before the next readiness barrier; replacement callbacks cannot reuse a previous incarnation's popup. Sequence numbers are monotonically increasing; revision and generation belong to the current view transaction. Native/GPU handles never cross IPC.
- Mouse events retain left/middle/right down masks and keyboard modifier masks across moves and wheel events, allowing real range dragging and modified pointer gestures. Focus loss/hidden views clear held input state. Back/forward buttons are ignored without worker failure or artifact navigation. Keyboard events map common physical Code values to Chromium VK identity, including punctuation, navigation/editing keys and function/numpad keys. Ctrl/Meta shortcuts emit RAWKEYDOWN/KEYUP only, not text CHAR; Enter emits CHAR carriage return so Chromium inserts textarea newlines. Composing key events do not duplicate CHAR input.
- Linux OSR uses physical view bounds and Chromium per-view zoom (`log(scale)/log(1.2)`) for CSS-pixel scale. This avoids Linux CEF ignoring dynamic OSR screen scale and prevents fractional-scale raster size drift. Input positions are physical view coordinates. Fractional bounds and real alpha pixels are tested.
- `was_hidden` suppresses OSR and Chromium rAF work while retaining the DOM; hidden and destroyed views never publish. Resume performs a fresh readiness round-trip, not a cached white-frame heuristic. Visible OSR is configured for 60fps. CEF external pump deadlines inform bounded sleeps; the loop backs off when all views are hidden, with no busy-spin. `Status.animating` currently reports visible rendering demand, **not exact JS-animation detection**.
- Shutdown/EOF closes browsers and pumps until `on_before_close` before calling CEF shutdown; closure has a 10-second timeout.

## Resource policy and residual limitations

Documents are synthetic `data:text/html` documents with opaque origins. Only the exact initial main-frame URL can navigate once. Subsequent navigation, URL-open requests, new browser windows, downloads, media/permission prompts, file dialogs, and blocking JS dialogs are denied. No privileged host JS bridge, file URL loading, workers, frames, forms, arbitrary network connections, or unrestricted HTTPS resources are exposed.

The leading CSP deliberately permits inline artifact scripts/styles and limited HTTPS script/style CDNs (`cdn.jsdelivr.net`, `cdnjs.cloudflare.com`), Google Fonts, and images (`images.unsplash.com`, `cdn.jsdelivr.net`, inline data images). Fetch/WebSocket connections are blocked with `connect-src 'none'`. Native resource interception additionally requires GET and exact HTTPS host/path prefixes; credentials, custom ports, host suffix tricks, local schemes, and disallowed redirect destinations are rejected. This is a limited allowlist, **not a DNS/IP firewall or CDN-integrity guarantee**. CDN content and engine vulnerabilities remain trust dependencies; Remote CDN/font availability is not exercised by the offline pixel regression; its opt-in online mode verifies pinned Chart.js actually loads and executes from jsDelivr.

The smoke test covers real grid/SVG pixels, input click/keyboard, wheel scrolling, autonomous rAF, live theme DOM preservation, resize, hidden/resume, source replacement, rapid generations, initial-hidden theme updates, fractional scaling, premultiplied alpha, local-network rejection, IPC integrity, and clean shutdown. It additionally exercises native SELECT popup painting, mouse selection, Escape closure/base restoration, popup invalidation across resize/replacement, native range dragging with Control and down-button masks, Ctrl+A replacement, Meta shortcut CHAR suppression, textarea newline insertion and shifted physical punctuation. Pure tests cover popup alpha blending/clipping, base restoration and readiness gating. It does not claim T3 parity. Native IME composition, non-US/AltGr keyboard layouts, double-click selection, drag-and-drop payloads, popup interaction at fractional zoom, and end-to-end desktop GUI have not been validated here. Linux is the tested platform; the `/dev/null` descriptor isolation and private-cache permissions are Unix-specific. Untrusted CPU/memory quotas, process supervision under renderer crashes, and adversarial readiness/sandbox audits remain separate work.

## Intrinsic layout metrics (protocol v2)

`ContentHeight { key, generation, revision, height }` reports authored content height in **unscaled browser CSS pixels**, not physical frame pixels. Initial metrics use the same theme/layout/two-rAF readiness transaction as frames and are written before available frames. Resize, source, theme and visibility transactions invalidate both pending pixels and metrics; old acknowledgments cannot relabel old measurements. Hidden/destroyed views never publish. ResizeObserver, DOM mutations, image load and font completion schedule at most one measurement per rAF; unchanged heights produce no metric packet.

Measurement uses authored element bounds and text ranges in document coordinates, not `documentElement.scrollHeight` or the viewport-floored body rectangle. Script/style/hidden content is ignored, authored internal overflow stays inside its box, and scrolling does not change the intrinsic measurement. No DOM wrapper or pixel-color crop is used. An optional `[data-neoism-artifact-root]` selects the authored content subtree. Body defaults to zero margin and transparent background; author CSS may override these defaults. Theme colors remain CSS variables, not an opaque full-viewport background.

Vertical viewport units and percentage-based vertical sizing have no unique intrinsic fixed point. Detectable authored declarations use a stable **640 CSS-pixel fallback** across fitted-height transactions; ordinary tall documents report their intrinsic height up to the 8192 CSS-pixel transport bound. The parent caps display height at 640 and keeps tall content internally scrollable. Measurement is bounded to 20,000 nodes; cross-origin stylesheet declarations inaccessible to CSSOM, shadow DOM, and continuously transformed content without resize/DOM changes are not fully covered by intrinsic sizing. This is not a general-purpose CSS layout solver.

Parent integration: consume `PumpOutput.layout_metrics` (`ArtifactLayoutMetrics { key, revision, height }`), cache by source revision + layout width + scale, **not fitted height**, and retain that cache across hiding. A new width must not reuse old metrics or frames. Request the final fitted viewport through reconcile/resize; the host generation barrier rejects prior geometry. Parent loading skeletons and row geometry are outside this crate.
