2026-10-14: User reported `/compact` stuck in `Neoism Download Landing Page and Vercel Setup`, session `ses_ec4ee5255ffeVweKZPx4S31IOY`. Live agent API `http://127.0.0.1:4096`, installed executable `~/.local/bin/neoism`, embedded workspace daemon PID 5247, runtime version `0.7.126-nightly.20261013.2`. DB `~/.local/state/neoism/agent.turso.db`.

Root failure: `session_context::compact_session_context` holds the root execution admission mutex while registering a transient run. `begin_manual_action` formerly always tried admitting a NEW top-level execution, which rejects an unfinished prior execution. Both start_run and manual-admission error branches then awaited `finish_session_run` without dropping admission; cleanup calls `finish_if_quiescent`, recursively taking the same mutex. Initial evidence: no compaction marker/provider request, latest transient run durably completed but runtime endpoint hung, coordinator/global status idle. The first exploration inspected durable runs/subtasks/provider segments but missed an in-memory background job; do not describe this session as fully quiescent at that point.

Source fixes in `neoism-agent/crates/neoism-agent-server/src/session_context.rs` and `execution_activity.rs`: drop admission before cleanup in both error branches; reconcile prior quiescence under the existing admission guard before registering the new transient run (locking wrapper + documented `finish_if_quiescent_locked` body); child manual admission reads and validates current/inherited execution directly instead of calling `ensure_for_prompt(false)` which recursively locked the same mutex. Follow-up live discovery also justified allowing top-level compaction to reuse an existing unfinished execution when background previews/child work keep it alive rather than requiring a brand-new execution. The admitting session's own coordinator run remains exclusive, and family work is not force-finished.

Regression coverage `manual_compaction_reconciles_idle_execution_and_releases_admission` covers idle prior execution, active prior provider segment with execution inheritance, child compaction with active parent, and orphan-child admission rejection. Checks durable transient run completion, coordinator release, reacquisition by runtime reconciliation, unchanged history on rejection, and expected execution identity/finished state. Uses isolated temp databases and neoism/stub. `cargo check -p neoism-agent-server --lib` and `--tests` passed (tests compile only, not run); final `--tests` rerun passed after adding root execution inheritance. `git diff --check` passed. Independent focused read-only review before the inheritance follow-up found no issues.
