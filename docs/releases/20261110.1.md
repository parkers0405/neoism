# Neoism v0.7.149-nightly.20261110.1

This nightly replaces the desktop app. `neoism` is now the native Rune frontend (`rune/app`) on Linux, macOS and Windows; the GPUiX app is no longer shipped. The workspace daemon, the agent service and the protocol are the same ones. Stable remains on v0.7.148.

## Changes

- The app is one native executable. It answers the command line the installers, the updater and the desktop integrations call (`--version`, `update`, the runtime check, `--new-window`, `--working-dir`, a folder or file to open) and starts the bundled workspace daemon when none is running.
- Multiplayer: everyone in a shared workspace on the activity rail, the people in a file on its row of the file tree, their carets, selections and name flags in the editor, and shared edits through the daemon's documents. Undo and redo revert your own edits only.
- A server or SSH system opens its own workspace tab, marked with a cloud. Dragging a tab onto a pane edge splits that side; onto a pane's centre or tab strip moves it there.
- Agent timeline: history loads ahead of the reader without moving the view, a jump-to-latest button and Ctrl+D, wide tables scroll sideways, thinking stays ahead of the reply it precedes, and scrolling, tool runs and streaming no longer re-run the views for motion.
- Editor: scrolling commits nothing, diagnostics pills open a list that jumps to the line, a code block's Copy button copies and says so.
- `exit` in a Home terminal closes its tab; close buttons are red; the mode pill settles on its last frame.

## Known gaps

- The Rune app has only been run by a person on Linux. The macOS and Windows bundles are built and gated by CI (they start, report their version, pass the runtime check and the installer and updater transactions); nobody has used them yet.
- Not carried over from the GPUiX app in this build: the Windows peer's orb effect, and local docs served over loopback (`neoism docs` opens the bundled pages directly).
- GPUiX's source is still in the repository and is not built by the release.

## Build provenance

The immutable release tag identifies the initial source snapshot. Platform bundles include `build-info.json` with their exact source commit, version, platform, and architecture; Windows bundles also record service hashes. Any necessary platform-specific retry uses an exact source commit without moving the tag or rebuilding successful platforms. Published payloads have SHA-256 sidecars.
