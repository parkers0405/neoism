Neoism is migrating LSP off the old Neovim/Lua path (`rio/lsp.lua`, 2827 lines) onto a **Rust-owned engine** we control. As of 2026-07-06 (uncommitted WIP, started by a parallel agent, continued by me).

**Engine (real LSP client, ours):** `neoism-agent/crates/neoism-agent-server/src/lsp.rs` (+ `lsp_service.rs` = persistent per-(root,language) client spawning real `rust-analyzer`/`gopls`/`pyright`/etc. over JSON-RPC; `lsp_client.rs` transport; `lsp_scan.rs` workspace detect; `lsp_languages.rs` = LANGUAGE_SPECS for 10 langs). Public API surface: hover/definitions/references/implementations/document_symbols/workspace_symbols/call_hierarchy/formatting/code_actions/resolve_code_action/execute_command/rename/diagnostics/status. `src/rust_lsp.rs` is a thin `pub` facade re-exporting types + `status`/`language_id_for_path`/`command_source`. `resolve_lsp_command(id, cmd)` (lsp.rs:~313, pub(crate)) classifies binary source → `LspCommandSource::{Extension(managed_bin_map from installed.json), Config, Path, Missing}`. `LspStatus` carries per-server capabilities + command_source.

**Daemon bridge:** `neoism-workspace-daemon/src/rust_lsp.rs` reads nvim active buffer → engine → maps results. `run_action` handles `EditorClientMessage::LspAction` (server.rs:~3237); Definition/Implementation auto-open first location via OpenBuffer. New `poll(session, root)` returns BOTH the `DiagnosticsFetch` and an `EditorServerMessage::LspSnapshot` for the pill, driven from the diagnostics poll loop (server.rs:~2946/2957).

**The split-brain (why it wasn't Zed-level):** engine did the WORK, but the SURFACES still read the old nvim/Lua path. Cutover state now:
- ACTIONS (hover/def/refs/symbols/format/rename/code-action) → Rust ✅. `LspActionResult` picker: DocumentSymbols now carries flattened `EditorLspSymbol` outline (name/kind/detail/loc/depth), daemon `flatten_document_symbols` depth-first→selection_range; desktop `maybe_open_lsp_action_result_modal` (lifecycle.rs) renders one navigable modal row per symbol/reference (OpenLspLocation), cap 300, `lsp_location_label`=dir/file:line.
- DIAGNOSTICS → fully Rust ✅ (2026-07-06). `rust_lsp::poll` now returns `(Option<DiagnosticsFetch>, Vec<EditorServerMessage>)` = [LspSnapshot, **Diagnostics**]; `diagnostics_message()` builds `EditorServerMessage::Diagnostics` (severity tally + editor::DiagnosticItem) from the engine's publishDiagnostics, emitted on the editor sink in server.rs poll loop. Daemon `rio_diagnostics` handler NEUTERED (was the ONLY desktop-chip source). Inline chips (render/mod.rs:~4261 `row=source_y` fix [[bug-inline-diag-lens-scroll]]) now Rust-fed. ~2s poll cadence (was real-time via nvim DiagnosticChanged) — acceptable tradeoff.
- STATUS-BAR PILL + click popup → NOW Rust ✅. Daemon emits `LspSnapshot` (built from `rust_lsp::status(root, file)` filtered by `language_id_for_path`, source badge via command_source). Legacy daemon `rio_lsp_status`/`rio_lsp_snapshot` handlers NEUTERED (return early) in `neoism-workspace-daemon/src/nvim.rs` so Rust is single-source (kept `rio_lsp_message` for live server notifications). Frontend consumes `EditorServerMessage::LspSnapshot`→`lsp_snapshot` field (tab.rs:~1431); render prefers it (render/mod.rs:~1249). NOTE: only `EditorBackend::Daemon` supports LSP; `Local` returns no-op for LspAction (tab.rs:~1645) — so daemon-path pill is the only one that matters.
- EXTENSIONS PAGE → NOW shows engine source ✅. Per-LSP-row badge (extension/path/config/missing, green=usable/red=missing) via `rust_lsp::command_source(id, manifest.run.command)` computed in `extension_manifest_to_entry` (desktop bridge extensions.rs), stored on `ExtensionEntry.lsp_source: Option<String>` (shared state.rs), rendered as leading chip in view.rs. Removed dead `refresh_managed_bin_map_in_nvim` (Rust re-reads managed_bin_map each status()).

(6) nvim's competing completion gated OFF by default in `rio/completion.lua` (only the trigger keymaps/autocmds 358-405; diagnostic config kept) behind `NEOISM_NVIM_COMPLETION=1` escape hatch. Snippet placeholders NOT expanded (snippetSupport:false). Web/wasm popup not wired (desktop only). Ctrl+P is still nvim keyword completion. Remaining: nvim's own LSP CLIENT starters (`s('rust-analyzer'…)` in ide_init_commands) can now be deleted since completion no longer needs them — kills the parallel clients + orphaned rust-analyzers ([[bug-nvim-lsp-orphan-swap]]).

**CRITICAL DESKTOP FIXES (2026-07-06, after first desktop test showed no completion + typing latency + empty pill):** (1) **Poll never ran on desktop** — the daemon diagnostics poll (now the SOLE source of desktop pill + inline diagnostics) was gated on `!diagnostics_subscriptions.routes().is_empty()`, but ONLY the web frontend sends `SubscribeDiagnostics` (ProtocolClient.ts) — desktop never does. Removed the gate: poll runs whenever `nvim_session.is_some()`. Without this, neutering `rio_diagnostics` had REGRESSED all desktop diagnostics. (2) **Completion blocked the socket loop** — the `LspComplete` handler `.await`ed `rust_lsp::completion` inline (spawn_blocking inside only frees the runtime, not this task), so every keystroke queued behind the engine round-trip (rust-analyzer cold start = seconds) → typing latency + stale-seq drops = no popup. Fixed: `tokio::spawn` the completion, route the reply back via `nvim_redraw_tx`. (3) **Pill "attached" state** — `detected_servers` only reports Available (command exists), never Connected. Added `lsp::live_languages(root)` (queries LspService.clients) → daemon marks servers whose language has a live client as "attached". (4) Env logs behind `NEOISM_LSP_LOG` at every hop: frontend trigger (`request_lsp_completion`)/reply (`apply_lsp_completions`), daemon completion request+result, daemon snapshot built (servers/live/diag counts). Run `NEOISM_LSP_LOG=1 target/debug/neoism`, filter `neoism::lsp`.

**ROOT CAUSE of "attached but 0 completions + 0 diagnostics" (2026-07-06, from user logs):** `lsp_service::default_initialization_options("rust")` sent rust-analyzer `diagnostics.enable:false` (diagnostics literally OFF) + `procMacro.enable:false` + `cargo.buildScripts.enable:false` — copied from the old nvim perf config. Without proc-macro/build-script expansion RA can't resolve types through derives (serde/async_trait) → completions EMPTY; diagnostics off → nothing pushes. FIXED: enabled all three. ⚠️ SUPERSEDED — `checkOnSave:false` + `allTargets:false` were NOT safe to keep; see the DEFINITIVE root cause below. ALSO fixed `ensure_open(file, None)` which re-read DISK for an already-open doc → clobbered the live buffer text so every query hit stale content: now `None` no-ops on an open doc; `service::completion` takes `text` and syncs the live buffer (didChange) before querying (threaded lsp::completion→rust_lsp::completion→daemon passes `Some(&buffer.text)`). Added `$/progress` + window/logMessage taps in the reader thread (advertise `window.workDoneProgress`) → `NEOISM_LSP_LOG` shows RA indexing so it's clear it's warming up (minutes on the neoism workspace; completions/diagnostics only start post-load). **Extension-page install landed a MISSING binary silently (2026-07-06).** `install_github_release` returned `install_dir/asset.bin` unconditionally — for tar.gz/zip that NEST the binary (`pkg/bin/server`) it pointed at a non-existent path, and `chmod` was best-effort-skipped if absent → a dangling symlink registered as "installed" → pill shows "Binary missing", LSP silently dead. **DEFINITIVE completion root cause = our `cargo.allTargets:false` (2026-07-06, PROVEN headless).** After every completion returned bare `null` (`raw_head=null`, not `{items:[]}`, not an error) even at valid `.`-positions, ruled out by READING code: error-misparse (client `wait_for_response` bails on `error` field → we'd log REQUEST FAILED, we didn't), URI mismatch (open + position both use the same `path_to_file_uri(file)` in lsp_uri.rs — identical), dropped responses. rust-analyzer was GENUINELY returning `null` = "no crate context for this file." Cause: `default_initialization_options("rust")` set `cargo.allTargets:false`, which runs `cargo metadata` WITHOUT `--all-targets` → example/test/bench targets are dropped from the crate graph → any file in `examples/`, `tests/`, or a `#[cfg(test)]` module is an ORPHAN → `null` on EVERY completion/hover/def. (Confirmed vs rust-analyzer manual; Zed uses the RA default `allTargets:true`.) FIX: `allTargets:true` + `checkOnSave:true` (the latter re-enables flycheck = real cargo-check diagnostics; `false` was why `diagnostics=0`). PROVEN by a headless LSP driver (`scratchpad/ra_probe.py` — speaks LSP to the real binary, waits for `$/progress` end, fires completion): with `allTargets:true`, `examples/completion_probe.rs` returns text.→122 items (as_str/len/push_str…), String::→62 (new/with_capacity…), numbers.iter().→76 (map/filter/count…). Pipeline was 100% correct all along; the config orphaned the test files. NOTE the earlier "wait for indexing / test at a non-field position" advice was necessary-but-insufficient — the config bug sat under it.
