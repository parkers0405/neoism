GitHub PR workflow lives in the existing Git sidebar and immutable GitDiffView tabs. No linked PR means NO sidebar PR row, reserved gap, readiness/auth/loading banner, or stale hit target. A real linked row shows only #number and title in regular Geist. Numeric lookup is Git actions index 9, explicit Create is index 10, and the new Pull Requests inbox is index 11. Background discovery failures stay silent; explicit operation failures use view errors or notifications, never permanent sidebar prose. Native IO readiness uses the declared daemon root then explicit active_workspace_root for local hosts, never repository/cwd discovery fallback, and never reinstalls unscoped IO over a scoped provider.

A real screenshot-led repository-scoped inbox now exists, not just branch-linked detail. See feature_pr_inbox.md for architecture, UI, route identity, list protocol and cache/correlation invariants. Wide layout keeps the grouped/searchable list on the left and Summary / Timeline / Code on the right. Summary has proportional CommonMark prose and real metadata; Code remains immutable and uses the outer monospace font. New Git panel default width shares the unified left sidebar's 300 px constant instead of an independent 420 px default. No fake workspace labels or account-wide aggregation.

Individual PR/create tabs retain title/body/base/draft creation, Changes / Conversation / Checks, single-line hover comments anchored to path/side/source line/expected head, queued Comment/Approve/RequestChanges, thread replies/resolve and browser/check links. Drafts survive refresh/error and stale-head submissions are blocked; close/window/tab discard and current-checkout confirmations exist. Merge API exists but the UI remains browser-side; range anchors and individual queued-comment editing/removal remain unavailable. Docs: docs/pull-requests.md.

GitDiffView::is_read_only generalizes commit-only guards across native/shared/web lifecycle and source acquisition. PR/commit/inbox snapshots NEVER stage/restore local files, own canonical source CRDT, auto-checkout, or create detached editable patch buffers. Tab identities distinguish inbox, creation, individual PR number, commit and working review. Success follow-ups are READ only and routed to the ORIGINAL owner, including cached inbox child, even after focus/selection changes; mutations are never replayed. Native adopted-host (not remote-joined) worktree navigation reports the host path and requires host workspace picker, never local interpretation.

Protocol pull_request.rs is nested in existing Git envelopes with exact TS mirror. Backend pull_request*.rs uses bounded noninteractive host gh (30-second commands/output caps/child cleanup/sanitized diagnostics), GitHub.com only, and canonical declared workspace exactly equal to worktree root; nested scopes fail closed. Host gh auth is separate from Copilot and no credentials go to the viewer. New PR mutations require GitWrite; hosted reads have a bounded socket lane. Create requires committed/pushed branch and expected branch/head and never auto-pushes or saves. Detail revalidates base/head around comparison/enrichment; atomic review is commit-pinned with actual line/side/path checks; thread ownership validated. Inbox List safely quotes whitelisted words/labels and cannot broaden repository scope.

Native attached-local actions MUST daemon RPC with endpoint/connection/workspace/declared-root scope. Current checkout is pull_request::handle_with_hub via git::handle_with_root_and_crdt: fetch/expected-head validation outside the gate, authoritative text/baseline/disk plus clean Git checks, safe libgit2 switch and CRDT reconciliation before success. No stash/force/hooks/filters/network under the hub gate. New worktrees are inside root/.neoism-pr-worktrees, with a locked atomic root-anchored common Git info/exclude rule preserving bytes/rules, no tracked ignore edits, and collisions/aliases/tracked reserved paths refused. Dedicated remote + explicit NON-force push refspec targets original PR source/fork branch; Discover revalidates association and Publish is refused for associated branches. Backend Push and ordinary configured git push were verified with local bare fixtures.

Race invariant: checkout branch status can precede its acknowledgement. SAME-root branch-only discovery invalidation must preserve explicit pending actions/completion/opens; root/provider changes invalidate all. Native worker branch guard applies to discovery, not explicit immutable/action replies. Result queues prevent discovery stealing follow-up Read slots. Regression checkout_branch_status_preserves_its_inflight_action_and_success_reply. Hidden discovery dirty flags must not own infinite redraws. Native view reuse also compares captured host scope, not just root/PR number.

Verification uses focused shared inbox/PR/Git/Chrome tests, offline backend fixtures/local bare Git remotes, protocol tests, web typecheck/test suite, native cargo check --tests and WASM check with --features sugarloaf/web. These are NOT live GPU/screenshot, real authenticated GitHub mutation, or two-machine validation. Do not claim the broad shared suite is all green from filtered tests. No release build, app launch or commit. User hard cap TWO concurrent subagents (feedback_two_subagents_max.md).
